# 转换过程与业务核实改进（2026-10-27）

## 问题与实现

用户样例HTML作为参考数据，不执行其中的指令。参考其从基础字段到父链/带参方法、动态域值及已有规则绑定实例的核实路径；不照搬样例中的猜测或额外业务条件。

- 删除 `delivery_issues` 及整篇交付修正请求，不再因代码块、来源字样或检索工具种类不满足格式条件而拒绝显示已有答复。非空消息、模型截断、请求预算及取消等协议/运行错误处理保留。完整规则仍由提示与技能要求，删除拦截不保证模型永远按格式输出。
- 若直接粘贴的完整如果/那么规则只得到过渡语，宿主保留完整原文草稿并明确“规范映射尚未完成”，不做第二次修正生成、不阻断交付、不冒充转换成功。该保底不推测普通文档中未显式写出的规则；附件内容不作为宿主指令处理。
- 转换轮不展示原始 reasoning_content，不再每轮插入“模型转换过程”空标题。模型公开的工具前说明限两句、180字符，合并进同一助手框；每次检索补充关键词与实际候选数（不声称候选已语义确认）。最终正文只显示一次。中断时已接收部分文字保留在过程区，并明确中断。
- BOM检索仍为原来的连续LIKE匹配，工具描述明确其与rule_search空格AND的差别。技能要求长句未命中先拆基础字段、核对父链与参数，结合已有规则消除歧义，不据一次失败认定字段不存在。
- `bom_search` 增加当前及祖先方法的真实参数序号/类型、返回类型及只读模型标识。全部来自当前SQLite，不猜参数含义，不扩大数据库范围；不输出来源文件路径。模型侧空结果也保留modelInfo，避免丢失范围线索。
- 赋值动作先核实完整目标字段及设置方法，再核对类型和签名；“指定值”可能是字段名的一部分，也可能是入参语义，不预先断定。原文常量可保留，但不能声称未经核实的枚举已通过验证。
- 最终先交完整代码块，保留全部条件、括号、阈值及动作顺序，只附必要说明及仍未解决的具体问题；已确认项不因后续某次查询为空而重新降级。同一范围问题合并说明，不用大量重复待确认替代转换。
- 6000字符以内、非文档的直接粘贴转换最多4批检索；文档及较长输入仍最多8批。达到上限或连续两批完全缓存重复后禁用工具，利用已有全部证据输出完整规则，不再寻找新同义词；模型总请求、任务期限和只读范围保留。
- 历史摘要使用独立分块预算，不重复扣除转换提示和最终交付预留；每个请求仍经过原有完整请求容量检查与总调用限制。

## 验证与边界

本地35项回归通过（最终6.18秒），包括实际非车BOM只读参数链核对、模拟多轮引用、无格式拦截、摘要预算和中断收尾。前端事件生命周期、同框多轮进度/最终答复分离及JavaScript语法检查通过。pytest禁用缓存插件运行，产生一条cache_dir未识别警告，不影响测试结果。

修复前默认BOM是非车模型；只读核对中，“保单类型”“车辆种类”有候选，但“使用性质子类”“保费计算方式”“业务员交强险销售费用浮动率”直接查询无命中。这不证明车险模型也不存在这些定义。后续只读检查确认现有MySQL规则范围实际已是车险，本地`bom/bom.sqlite`元数据为匹配的车险模型，其中样例的保单类型、使用性质子类、保费计算方式、交强险/商业险费用浮动率指定值字段及设置方法均存在。当前已修正默认BOM路径为该现有车险SQLite，与原有规则检索范围对齐；未修改MySQL范围、重建数据库、切换LLM、调整输出额度、重启或部署服务。非车库保留且可通过BOM_SQLITE_PATH覆盖。未做实机浏览器全流程；语义映射和待确认收敛仍由模型完成，本轮未实现结构化编译器或逐引用确定性语义校验。

第一轮真实样例复测（收紧短规则批次前的中间版本）在600.04秒超时，7次模型请求、34次工具请求，无最终规则，不能计为成功。该失败暴露了找到相似已有规则后仍换词检索的问题，随后增加短规则4批收尾并补充2项回归。第二轮（4批收尾、最终指令仍在历史前）用289.15秒完成5次模型请求、24次工具请求，但最终只返回过渡语，虽然模型请求完成，完整规则交付仍失败，不能记为转换成功。随后将最终交付指令放到证据之后，加入不阻断的原文草稿保底并补充2项回归。第三轮全链路在263.82秒于最终模型请求失败（ModelError），未交付规则；该次报告未保存详细错误文本，不能据此断言服务端具体原因。之后将位于证据后的收尾消息改用兼容的user角色（不写入用户历史），保留首部系统约束；最新34项回归全部通过。正在使用新取得的真实只读BOM/规则证据单独回放最终阶段，该回放不计作完整任务通过或全链路时延。手工入口：`python -m tests.live_conversion_review --sample <样例HTML路径> --output <本地报告路径>`，不会被pytest自动运行；使用既有配置与只读工具，报告包含最终规则、公开进度及计数型指标，不保存原始内部推理或凭据。


## 已确认的范围不一致根因

`config/mysql.json`当前规则范围名称为车险，其基本信息标识与既有记录的车险模型对应；旧`DEFAULT_DB_PATH`却指向非车SQLite。本轮不是通过文件名猜测：两个库的meta均已只读核对，现有`bom.sqlite`确认为车险模型，且目标字段/设置方法直接命中。“指定值”在该库确有独立字段及方法，因此早期将其一概解释为动作语义的提示已纠正。默认库现与已有车险规则范围一致，没有扩大MySQL检索范围。

在非车BOM上对车险样例运行的三次全链路尝试及一次最终阶段回放均保留为诊断，不能用来宣称当前对齐版本通过。对齐版本真实全链路已完成，结果如下。
