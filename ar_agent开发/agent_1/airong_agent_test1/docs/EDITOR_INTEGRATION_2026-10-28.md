# 转换排版、检索收尾与编辑器校验（2026-10-28）

本轮检查与开发针对用户四张截图。编辑器地址由用户提供，用户明确授权读取其本机已有配置并正常登录；仅调用登录、检索、预定义候选、粘贴整理、标注与离线生成接口，未调用上传/保存接口，未改编辑器源码、数据库或认证配置。

## 实现

- `authoring.py` 对明确包含如果/那么的无围栏答复补代码框，不改变条件、动作或原有说明；已有围栏和非规则答复保持原样。说明/来源/待确认项留在框外，不恢复格式拒绝或整篇模型修正。
- 对本轮实际查到的单参数 void 设置方法，仅将相同目标的方法前缀按真实 label 拼回，消除“设置 保单… 为 …”导致的方法匹配错误；未知目标、参数值及注释不改。不是任意动作语义修复。
- 检索收尾从仅识别完全相同请求缓存，扩展到识别相同候选证据/空结果。第一批建立基线，随后连续两批没有新增候选就收尾；错误和未知返回形状不作为证据耗尽，保留短规则4批/长文档8批及原总预算。不同关键词返回相同BOM候选时，模型侧复用引用并保留当前关键词、limit、truncated；原始工具消息/事件不改，不跨任务复用。
- Skill与最终收尾提示补充根对象/别名、枚举逐字名称、空格、前两批集中核实动态域与方法、未填参模板不能冒充已绑定等要求。模型自主映射仍可能出错，不将这些提示当作编译级保证。
- 新增宿主 `editor.py`。本机 `config/rule-editor.json` 仅保存编辑器 URL 和用户已有登录配置路径，不保存凭据。默认无此文件不启用；可用 `RULE_EDITOR_CONFIG` 指定。运行时在内存读取已有 YAML 配置并正常登录，按编辑器网页先粘贴整理、再折叠标题/条件和逐动作分流，调用 `/api/generate_rule`。不注册新模型工具，不向模型传认证信息。
- 离线校验总期限25秒，网络/认证/异常均不隐藏规则，不追加模型整篇重写。明确标记未校验或未通过的完整草稿，计数型 `editor_validation` 指标不记正文/凭据。取消继续传播。
- 仅凭编译成功不足以证明绑定正确：宿主检测本轮BOM证据中带真实参数的祖先方法是否仍以完整未填参模板出现在规则正文中；命中则明确待核对。该检查不能覆盖任意错误实参或原文语义。
- `/api/health` 新增 `runtimeRevision=conversion-20261028-1`，用于确认进程加载的新版本；不证明模型、数据库、编辑器业务链路健康。
