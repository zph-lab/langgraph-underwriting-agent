# 文档编辑器开发与交接文档

核对日期：2026-11-03。语法状态已按本次回退更新。本文的“文档编辑器”指页面上的 **adp规则编辑器**，用于编辑中文保险业务规则，不是 Word 文档编辑器。

本文以当前源码和本地数据核对结果为准。命令默认从合并项目根目录执行；说明中以 `E` 表示 `rule_editor_new/`，不是需要创建的环境变量。启动步骤见[启动部署文档](03_项目启动部署文档.md)，助手调用编辑器的方式见[业务助手开发文档](02_Agent业务助手开发文档.md)。

## 1. 接手后先理解什么

编辑器把中文业务规则转换为 ADP 接受的结构，主要能力是自由文本编辑、BOM 候选补全、标注与校验、离线生成、上传 ADP 和条件命中测试。当前 v2 主流程由业务模型和确定性代码驱动，未使用大模型完成编辑器解析；配置中的 `llm.enabled=false`、`search.use_semantic=false`，不能把 `llm/`、`rag/` 的存在描述为已接入在线 AI。

典型操作顺序是：输入或粘贴规则 → 整理文本 → 查看标注 → 生成上传参数 → 填写本地测试数据 → 按需向已确认的 ADP 环境上传。生成与上传是两个步骤，离线生成不需要 ADP token。

建议第一天按以下顺序阅读：

1. 根目录 `README.md`、`merged_app.py`、`start.py`，理解合并挂载。
2. `E/AGENTS.md`、`E/rule_editor/service.py`、`E/rule_editor/api/routes.py`。
3. `E/rule_editor/core/textsearch.py`，沿候选、分词、标注调用链阅读。
4. `E/desc_to_rulecontent/rule_desc_to_content.py`、`parameterized_paths.py`、`selector_values.py`。
5. `E/desc_to_rulecontent/write_rule_to_adp.py` 和相关回归。
6. 最后阅读前端 `E/rule_editor/web/app.js`，对照页面操作与请求。

## 2. 术语与数据边界

| 名称 | 含义及注意事项 |
| --- | --- |
| BOM | 业务对象模型，定义对象、字段、方法、类型、枚举及参数；不保存某张保单的实际值 |
| 中文路径 | 如“保单的车辆信息的车龄(年)”，来自业务模型完整父链 |
| `fieldPath` | 底层业务引用，如 `appbase.getCoverage().namt` |
| `ruleDesc` | 提供给转换器的条件文本；接口另有原文及预定义、动作参数 |
| `ruleDescRaw` | 编辑器原始多段文本，生成前优先用它做与预览一致的校验 |
| `ruleContent` | ADP 条件树，不等于包含全部预定义和动作的完整规则 |
| 方法注册表 | 将 BOM 方法与真实平台 `expressionId`、参数模板对应 |
| `bomBaseInfoId` | 模型基础信息标识，不能与 `bomModelId` 混用 |
| 本地求值 | 主要检查如果条件，不能替代完整 ADP 引擎或动作执行 |

条件树常见节点为 `LOGICAL`、`COMPARISON`、`FIELD`、`CUSTOM`、`EXPRESSION`、`METHOD`。`paramValue` 在不同节点里可表示常量、参数映射或子节点。BOM 原始 `path` 与生成树中的位置路径可能含义不同，不要仅凭键名混用。

## 4. 实际运行链路

```text
浏览器 / → /api/search、/api/annotate、/api/normalize_rule
          → routes.get_svc() → EditorService → TextSearchService
                                 ├─ SQLite BOM 路径索引
                                 └─ 源 BOM 的方法、类型、字典信息

生成 → _validate_rule_text → _annotate_text
     → generate_payload → RuleGenerator + 预定义/动作转换
     → generated（离线结果）

上传 → upload_generated → upload_payload
     → 预定义、规则、那么/否则等外部请求

本地测试 → test_rule_local → Evaluator → 命中及诊断树
```

`get_svc()` 懒加载并复用服务，BOM 路径、字典、注册表及配置存在进程内缓存。修改 Python、BOM 或主要索引后，需要重启合并服务。仅修改 HTML/JS/CSS 通常刷新即可；命中浏览器缓存时强制刷新。

合并入口先挂 `/assistant`，再挂编辑器到 `/`；顺序反过来会被根应用截获。两个页面通过右上角原生链接整页跳转，不再以 iframe 保持工作区 DOM。编辑器旧 `#rule-ai-assistant` 地址重定向到 `/assistant/`。

## 5. 配置与模型配套

配置文件是 `E/rule_editor/config.yaml`。`config.py` 将键尾为 `_path`、`_dir`、`_db` 的相对路径锚定到 `E`；`repository_file`、`catalogue_file` 等不符合该后缀的配置由相应调用方处理。不要假设所有路径都相对终端 cwd。

截至核对日：

- `data.bom_path` 为 `新车险915/bom.json`，`data.samples_dir` 为 `新车险915`。
- 核心索引是 `data/bom_catalog.sqlite`，本地 `fields` 表有 15,025 行；此数量只是一份核对快照。
- 配套注册表 `desc_to_rulecontent/bom_methods_新车险915.json` 存在。
- `login.enabled=true`；真实账号、密码及 ADP token 只保留在原本地配置，不写入交接文档。
- 独立编辑器配置端口为 8009；合并运行时实际 host/port 由根目录启动参数决定。

| 配置段 | 用途 |
| --- | --- |
| `data` | BOM、语料目录、库/分类源文件 |
| `etl` | `bom_db`、`value_dict_db`、`freq_stats_db`、`corpus_db` |
| `login` | 本地登录开关、账号、密码 |
| `upload` | ADP URL、规则名、模型关联 ID、token 默认配置 |
| `server` | 仅独立模块入口读取的 host/port/reload |
| `search`、`candidate`、`llm` | 检索及历史扩展配置；是否有效以调用链为准 |

**BOM 定义业务入口和参数；`rule_model.txt` 定义平台真实方法 ID。** 方法注册表默认按 `samples_dir` 末级目录名选择；找不到时存在回退 `bom_methods_非车.json` 的逻辑。换模型必须显式核对文件名和内容，不能把“没有抛异常”当成配套正确。

助手的 `bom/bom.sqlite` 与编辑器的 `data/bom_catalog.sqlite` 是不同 schema、不同消费者的数据，不能相互替换；即使模型名一致，也不能比较总行数就认定是否一致。

## 6. API 速查

下表是合并部署中的真实路径。部分业务失败通过 HTTP 200 的 `success:false` 返回，客户端必须检查响应体。

| 接口 | 用途及边界 |
| --- | --- |
| `GET /api/health` | 基础 HTTP 健康；不证明 BOM 初始化或 ADP 可用 |
| `GET /api/boot_id` | 进程启动标识，参与前端缓存清理 |
| `POST /api/login`、`/api/logout`；`GET /api/auth_check` | 本地登录与 Cookie 检查 |
| `GET /api/search` | `word/prev/prevprev/limit/predefines` 候选 |
| `GET /api/annotate` | 整段文本标注，调用 `_annotate_text` 按规则区块分流 |
| `GET /api/normalize_rule` | 主系统粘连文本整理，返回 `text` |
| `GET /api/selector_context` | 当前字典取值区间及选项 |
| `GET /api/predefine_search`、`/api/predefine_param_context` | 预定义候选及参数位置 |
| `GET /api/method_search`、`/api/method_param_context` | 动作方法候选及参数位置 |
| `GET /api/repositories`、`/api/catalogues` | SQLite 库/分类列表 |
| `GET /api/upload_defaults` | 上传卡片默认参数，按敏感配置处理 |
| `POST /api/generate_rule` | 离线生成；不访问 ADP、不要求 token，但有关联模型 ID 的前置检查 |
| `POST /api/upload_generated` | 上传传入的已生成对象，不重新编译 |
| `POST /api/upload_rule` | 兼容的一键生成上传入口，会访问外部 ADP |
| `POST /api/test_rule_local` | 本地条件求值 |
| `POST /api/test_rule_hit` | 外部 ADP 测试，不作为纯离线检查 |

最小离线生成请求可用：

```json
{
  "ruleId": "LOCAL_HANDOVER_ONLY",
  "ruleDesc": "保单的车辆信息的车龄(年) 小于 7",
  "ruleDescRaw": "如果 保单的车辆信息的车龄(年) 小于 7"
}
```

含完整四段式时，`predefineContent`、`thenText`、`elseText` 分别传递，不能把整段正文都塞进 `ruleDesc`。`ruleDescRaw` 保留完整编辑形态，用于前置校验。前端生成后若文本或相关参数改变，会要求重新生成；该指纹是页面一致性机制，不是后端对传入 `generated` 的完整安全证明。

## 7. 必须保留的语法和行为

### 条件组合与类型

- 同层“并且/或者”按文本顺序左结合，不采用其他语言 AND 高于 OR 的规则。复杂范围用英文 `()` 明确分组。
- 算术输出以“加/减/乘/除”为主，并保留现有符号输入兼容；预定义表达式有自己的解析路径。
- 区间采用“在 起值 和 止值 之间”，保留旧语法兼容；缺项、占位未填及类型错误仍须拦截。
- 字典支持单选、多选及否定形式，中英文括号兼容；值必须属于该字段 `codeService` 对应域，不得全局找同名枚举兜底。
- 预定义别名需要跨行注入、检查重复别名，并在本地求值时保持列表多个条件绑定同一个元素。

### 方法、字段与括号

字段名可以合法包含数字、逗号、空格、斜杠及括号。识别时先保留 BOM 完整语义单元，再判断运算符。

```text
保单的险别0, 险别(动态域集的险别代码的第三者责任险)的保额/限额(元) 大于等于 1000000

保单的险别列表包含0, 一些险别中的一个(动态域集的险别代码的第三者责任险) 为 是
```

前者是返回对象的方法下钻字段，现有共用匹配器保留叶子类型及 `exprNode.paramValue`。后者在业务语法上是布尔方法调用，但本轮新增识别影响其他语法，已按用户要求回退；当前仍可能被误拆为普通列表“包含”，不得据此声称预览或生成正确。当前共用匹配器只处理标签中恰有一个 `()` 的方法子字段模板，不是任意多层嵌套方法解析器。非法参数、未知字段、缺括号不能因消除红色而放行。

此前新增语法版本的 38 项通过记录不再代表当前代码；该版本已按用户反馈撤销。回退后使用原有参数化路径、字典选择和求值器回归重新检查，结果以本次回退记录为准，不代表全部业务语法或 ADP 真执行验收。

### 登录、上传与页面状态

编辑器本地登录和 ADP token 是两套认证。`re_session` 是 HttpOnly Cookie，服务端会话仅在进程内存，重启后失效；账号密码都为空时拒绝登录。保留用户已配置的登录信息，不能用清空配置处理规则错误。

上传会分别保存预定义、规则和动作，没有跨 HTTP 请求的统一事务回滚；失败可能已经部分保存。同 `ruleId` 可能更新已有规则，必须明确目标环境和编号。开发时默认用离线生成或 mock，不向真实 ADP 写规则。

浏览器草稿及页面快照存 localStorage，不是服务器规则档案；`bootId` 变化会清理旧编辑缓存。重启或换浏览器前，先导出重要规则文本，不能保证草稿永久恢复。

## 8. 常见开发任务怎么做

| 任务 | 推荐修改顺序 | 最低验证 |
| --- | --- | --- |
| 合法字段被标红 | 源 BOM/SQLite → 路径索引 → 分词 → 找路径 → 类型/相邻/括号校验 | 原例、最小例、非法反例、生成字段和参数 |
| 粘贴后才报错 | `normalize_pasted_rule`、`_norm_if_line` → 标注 → 生成 | 粘贴与直接输入含义一致 |
| 新增运算符 | 运行时词表 → 类型兼容表 → 标注 → 转换 → 求值 → 前端候选 | 正反例、边界值、旧语法；按需 ETL |
| 新增字典能力 | `selector_values.py` → context API → 候选 UI → 转换 | 域隔离、单/多选、非法值 |
| 调整动作转换 | BOM 方法 → 注册表真实 ID → 模板/槽位 → `build_item` | 真实模板、重载、参数顺序与类型 |
| 改上传编排 | routes → `upload_payload` → 失败反馈 | mock 外部请求及部分失败，不真写 ADP |
| 换业务模型 | 配套源文件、配置、ETL、注册表一起核对 | 新旧字段、预定义、动作、库分类、离线生成 |

复现完整多段规则时，走 `_annotate_text`；`service.annotate()` 是规则行入口，不能把整篇文本直接传进去，再据此认定页面有错。修复后不仅检查颜色，还检查生成树的字段、类型、参数、比较方向及条件分组。

换模型的管理命令在 `E` 目录执行，使用项目 Python；执行前确认备份和目标路径：

```powershell
# 方法表重新导出或模型变更时使用；不会上传 ADP。
python desc_to_rulecontent/write_rule_to_adp.py --gen-methods-model "新模型/bom.json" --model-methods "新模型/rule_model.txt"
# 根据当前 config.yaml 重建索引，不是日常启动步骤。
python -m rule_editor.etl.run_etl
# 仅更新库/分类对照时可选，重建相应表。
python -m rule_editor.etl.repositories
```

`run_etl` 重建 BOM、值字典、频次、语料索引及库/分类相关数据，运行前停止相关服务并备份。不照抄历史文档中不存在的 `_restart8009.ps1`。详细数据格式可参考旧[数据更换指南](../rule_editor_new/数据更换指南.md)，启动方式以本次合并部署文档为准。

## 9. 验证与故障定位

命令从 `E` 目录执行，`python` 必须是已安装本项目依赖的解释器：

```powershell
python -B -m unittest rule_test.test_parameterized_paths rule_test.test_selector_values rule_test.test_rule_evaluator -v
node rule_test/test_selector_ui.cjs
```

第二条需要 Playwright 和 Edge，使用模拟接口，不代表 ADP 联调。根目录另有 `tests/test_merged.py` 和 `tests/navigation.cjs` 检查合并挂载、原登录、API 和导航，见部署文档。

| 现象 | 优先排查 |
| --- | --- |
| 首页正常、候选失败 | 登录 401、SQLite 路径、懒加载初始化、BOM 与库是否配套 |
| 候选正确但生成失败 | 原文分流、预定义注入、转换器识别、动作注册表 |
| 方法参数段标红 | 完整调用是否先于运算符识别；粘贴整理是否拆坏方法名 |
| 上传要求 token | 本地 Cookie 不等于 ADP token，检查用户提供的有效 token |
| 生成通过但 ADP 失败 | 目标平台、模型/库/分类 ID、方法 `expressionId`、失败阶段 |
| 本地命中不符预期 | 输入缺字段、未填值、列表绑定、条件分组及求值器覆盖范围 |
| 改了代码页面无变化 | Python/BOM 缓存需重启；静态文件浏览器强刷；确认实际监听进程 |

交付一次修改时说明：根因、修改文件、合法输入恢复情况、非法输入仍拦截的证据、实际测试、是否需要 ETL/重启、是否做过浏览器和 ADP 验证。
