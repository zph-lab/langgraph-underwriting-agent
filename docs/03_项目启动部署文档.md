# 核保工作台启动与部署交接文档

核对日期：2026-11-03。适用于当前合并项目：**adp规则编辑器 + 规则AI助手，一个 Python 进程、一个 HTTP 端口**。

本文是新接手人员的启动入口。业务实现分别见[文档编辑器开发文档](01_文档编辑器开发文档.md)、[Agent 业务助手开发文档](02_Agent业务助手开发文档.md)。下列命令不包含真实账号、密码、API Key 或 ADP token。

## 1. 先看当前部署形态

```text
浏览器
  └─ Python / uvicorn：start.py → merged_app:app，单 worker
       ├─ /、/static/*、/api/* → rule_editor_new/rule_editor/api/main.py
       └─ /assistant/、/assistant/api/* → 助手 backend/main.py
            ├─ Python → 私有模型 HTTP 服务
            ├─ Node 子进程 → 本地 BOM SQLite
            ├─ Node 子进程 → 业务 MySQL（已有规则，只读查询）
            └─ Python → 同端口 /api/*（编辑器离线复核）

编辑器上传/远端测试 → ADP（用户显式操作时才需要）
```

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:8009/` | 默认编辑器入口 |
| `http://127.0.0.1:8009/assistant/` | 默认助手入口，末尾斜杠保留 |
| `/api/health` | 编辑器基础健康 |
| `/assistant/api/health` | 助手运行层、Node 和持久化状态 |

顶部导航整页切换，两页同源；无需额外启动 8712。复制助手答复后进入编辑器，仍需手动粘贴。切换页面会断开原页面连接，不能承诺未发送附件或运行中任务的界面状态完整保留。

`merged_app.py` 显式管理两个子应用 lifespan；仅挂载而不进入生命周期，会导致助手检查点等未初始化。`/assistant` 挂载必须早于 `/`。如果没有特定调试需要，始终用根目录统一入口。

## 4. 当前电脑快速启动

在 `C:\Users\admin\Desktop\合并` 打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

打开 `http://127.0.0.1:8009/`。终端保持打开，按 Ctrl+C 停止。脚本按以下顺序选择解释器：

1. 根目录 `.venv/Scripts/python.exe`。
2. 助手目录 `ar_agent开发/agent_1/airong_agent_test1/.venv-langgraph/Scripts/python.exe`。

注意：`rule_editor_new/.venv` 是编辑器环境，但不在统一脚本自动选择顺序中。当前电脑能否直接启动，以所选解释器是否存在、包是否完整为准。

换端口：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8010
```

此时两页都走 8010。局域网监听：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8009 -BindHost 0.0.0.0
```

其他电脑访问服务器真实 IP，而不是 `0.0.0.0` 或自己的 `127.0.0.1`。同时核实防火墙和网络路由。当前助手没有完整登录和会话归属控制，局域网可达前应按第 10 节设置访问边界。

`start.py` 会固定 cwd 为项目根目录、设置 `PORT`、校验端口范围并启动一个 worker。`start.ps1` 默认传 8009；直接调用 `start.py` 时可从 `PORT` 取默认值。

| 编辑器模型 | `rule_editor_new/新车险915/` 中的 BOM、方法表、库/分类对照 |
| 编辑器索引 | `rule_editor_new/data/`，尤其 `bom_catalog.sqlite` |
| 编辑器方法注册表 | `rule_editor_new/desc_to_rulecontent/bom_methods_新车险915.json` 及当前实际使用文件 |
| 助手模型与提示 | 助手 `.pi/settings.json`、`.pi/models.json`、`APPEND_SYSTEM.md`、`skills/` |
| 助手连接配置 | 助手 `config/mysql.json`、`config/rule-editor.json` |
| 助手 BOM | 助手 `bom/bom.sqlite` 与可追溯的源 JSON |
| 助手历史（需要恢复时） | 助手 `config/langgraph/`；可选旧 `config/pi-agent/` |

配置可能含明文凭据，不通过公开文档、工单日志或共享仓库传播。不要把历史非车库、临时重建库和稳定备份当成当前默认数据。

### 5.2 创建合并 Python 环境

从项目根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

如需更贴近助手既有锁定环境，可在创建空环境后改用：

```powershell

.\.venv\Scripts\python.exe -m pip check
```

这不是整个合并项目的完整锁文件：编辑器仍有范围依赖，需保存实际安装清单并跑相关回归。锁文件包含开发/测试依赖；不要把系统或其他项目的环境直接覆盖成这份列表。

### 5.3 安装业务 Node 依赖

从根目录执行，安装位置是助手业务目录：

```powershell
Push-Location "ar_agent开发/agent_1/airong_agent_test1"
npm ci --ignore-scripts
Pop-Location
```

不在 `pi-main` 安装/构建整套 workspace 来解决当前业务 Node 依赖。已有完整数据时不重跑 ETL，也不重建 BOM 库。

### 5.4 核实配置后启动

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

首次启动需确认：模型配置对应服务存在、业务数据库账号与范围配套、编辑器登录已配置、所有相对路径能解析。迁移时不要清空登录、自动切模型或修改业务范围来“先跑起来”。

## 6. 配置说明与端口规则

| 配置位置 | 要核对什么 | 生效与边界 |
| --- | --- | --- |
| 编辑器 `config.yaml` 的 `data/etl` | BOM 源与索引路径 | 缓存；变更通常需重启 |
| 编辑器 `login` | enabled、username、password | 进程内 Cookie 会话，重启需登录 |
| 编辑器 `upload` | URL、token、模型 ID | 不参与助手模型认证 |
| 助手 `.pi/settings.json` | 默认 provider/model | 不是 Pi 仍在运行的证据 |
| 助手 `.pi/models.json` | 地址、密钥、协议、上下文/输出额度 | 不输出文件全文到诊断日志 |
| 助手 `config/mysql.json` | mysql 与 `ruleSearch` 范围 | 文件仍须存在，环境变量不能替代文件存在性 |
| 助手 `config/rule-editor.json` | 原编辑器 profile | 合并入口仅在 profile 存在时启用并覆盖 URL/登录路径 |

助手模型覆盖变量有 `AGENT_MODELS_FILE`、`AGENT_PROVIDER`、`AGENT_MODEL`、`AGENT_BASE_URL`、`AGENT_API_KEY`；工具有 `AGENT_NODE`、`BOM_SQLITE_PATH`；数据库有 `RULE_MYSQL_HOST/PORT/USER/PASSWORD/DATABASE`、`RULE_BOM_BASE_INFO_ID`；运行预算有 `AGENT_TASK_TIMEOUT_SECONDS`、`AGENT_MODEL_REQUEST_LIMIT`。

核对日磁盘默认模型是 Qwen3.8-27B-NVFP4，助手 BOM 默认是车险 `bom/bom.sqlite`。环境变量和新配置可能覆盖这些值，历史 DeepSeek/非车说明不作为启动依据。

统一入口根据 `PORT` 将助手离线复核 URL 指向本进程的 `127.0.0.1`，因此改端口优先使用 `start.py/start.ps1`。直接运行 `uvicorn merged_app:app --port ...` 却不设置同值 `PORT`，可能让复核访问错误端口。合并模式不读取编辑器 `server.host/port` 来决定监听，也不通过旧助手 8712 对外提供页面。

## 7. 启动验收：分层检查

### 7.1 页面与基础健康

在服务终端之外另开 PowerShell：

```powershell
$baseUrl = 'http://127.0.0.1:8009'
(Invoke-WebRequest "$baseUrl/" -UseBasicParsing).StatusCode
(Invoke-WebRequest "$baseUrl/assistant/" -UseBasicParsing).StatusCode
Invoke-RestMethod "$baseUrl/api/health"
Invoke-RestMethod "$baseUrl/assistant/api/health"
```

预期两页 HTTP 200，助手 `runtime=langgraph`、`persistenceReady=true`、Node 路径有效。health 不调用真实模型/MySQL，不能据此宣布业务可用。

### 7.2 编辑器登录与离线生成

先在页面完成登录，检查候选、标注和生成。需要脚本检查时可使用下面的当前 PowerShell 会话，不把密码写进命令历史：

```powershell
$baseUrl = 'http://127.0.0.1:8009'
$editorCredential = Get-Credential -Message '输入已配置的编辑器本地账号'
$loginBody = @{
    username = $editorCredential.UserName
    password = $editorCredential.GetNetworkCredential().Password
} | ConvertTo-Json
$null = Invoke-RestMethod "$baseUrl/api/login" -Method Post -ContentType 'application/json' -Body $loginBody -SessionVariable editorSession
Invoke-RestMethod "$baseUrl/api/auth_check" -WebSession $editorSession
Invoke-RestMethod "$baseUrl/api/search?word=%E4%BF%9D%E5%8D%95&limit=3" -WebSession $editorSession
$generateBody = @{
    ruleId = 'LOCAL_HANDOVER_ONLY'
    ruleDesc = '保单的车辆信息的车龄(年) 小于 7'
    ruleDescRaw = '如果 保单的车辆信息的车龄(年) 小于 7'
} | ConvertTo-Json
$generation = Invoke-RestMethod "$baseUrl/api/generate_rule" -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($generateBody)) -WebSession $editorSession
$generation.success
```

此步骤只离线生成，不上传。`login.enabled=false` 的环境可跳过登录；不可为了验收临时禁用已有登录。脚本不打印密码/Cookie，运行后不保留含凭据变量到共享记录。

### 7.3 助手与外部依赖

页面先用一个简短问题测试字段查询，确认收到最终答复且 busy 结束，再测试已有规则查询和一条短规则转写。真实问答会访问配置的模型，查询已有规则会访问 MySQL；应在指定环境执行，结果人工核对。

附件可用无敏感内容的小 TXT 测提取，再检查 PDF/DOCX 和不支持格式反馈。验证离线复核提示，确认没访问 ADP 保存接口。真实 ADP 写入不属于启动默认验收；需要时另明确目标环境、库/分类及规则编号。

### 7.4 自动回归入口

以下从根目录开始，假设已建立根 `.venv`。开发环境如缺 pytest：

```powershell
.\.venv\Scripts\python.exe -m pip install -r "ar_agent开发/agent_1/airong_agent_test1/requirements-dev.txt"
```

## 8. 日常停止、重启与日志

前台启动用 Ctrl+C，统一 lifespan 会停止助手任务、工具进程并关闭检查点。重启后编辑器 Cookie 失效，部分编辑缓存可能因 bootId 变化清理，先导出未保存规则；助手正在生成的任务不会自动续跑。

端口占用时先确认进程，不能批量结束全部 Python：

```powershell
$listeners = Get-NetTCPConnection -LocalPort 8009 -State Listen -ErrorAction SilentlyContinue
$listeners | Select-Object LocalAddress, LocalPort, OwningProcess
foreach ($listener in $listeners) {
    Get-CimInstance Win32_Process -Filter "ProcessId=$($listener.OwningProcess)" |
        Select-Object ProcessId, ExecutablePath, CommandLine
}
```

确认是本项目后，从它的原终端停止；托管部署从服务管理器停止。根目录没有 `_restart8009.ps1`，不要照旧数据指南寻找该脚本。`start.ps1` 不会自动杀掉占用端口的进程。

默认日志输出到当前终端，没有统一的自动日志轮转配置。临时需要落日志，可在根目录执行：

```powershell
New-Item -ItemType Directory -Path logs -Force | Out-Null
powershell -ExecutionPolicy Bypass -File .\start.ps1 *> .\logs\workbench.log
```

这仍是前台进程，终端需保持打开。持续运行交给进程管理器并配置轮转、保留期限与访问权限，不把重定向日志当成已部署服务。助手 `agent_diagnostic` 提供阶段耗时、调用计数、usage 等受限元数据；不要新增全文提示、附件、密钥和连接信息日志。

## 9. Linux 与服务托管

`start.py` 不依赖 PowerShell。将完整项目放到如 `/srv/underwriting-workbench`，安装对应 Python/Node 环境与依赖后，从该目录启动：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm --prefix ar_agent开发/agent_1/airong_agent_test1 ci --ignore-scripts
.venv/bin/python start.py --host 127.0.0.1 --port 8009
```

本机配置可能包含旧 Windows 绝对路径，迁移到 Linux 需逐项替换；合并入口会覆盖已有编辑器 profile 的登录配置路径，但不会替你修复所有自定义路径。目录需允许运行账号写助手 `config/langgraph/`，以及测试/日志目标；业务源 BOM 和配置可按最小权限读取。

下面是 **systemd 配置示例，尚未在当前 Windows 环境部署验收**。运行账号、项目路径、Node 路径和环境文件需按服务器实际设置：

```ini
[Unit]
Description=Underwriting Workbench
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=workbench
WorkingDirectory=/srv/underwriting-workbench
Environment=PYTHONUNBUFFERED=1
Environment=PYTHONUTF8=1
Environment=AGENT_NODE=/usr/bin/node
EnvironmentFile=-/etc/underwriting-workbench.env
ExecStart=/srv/underwriting-workbench/.venv/bin/python /srv/underwriting-workbench/start.py --host 127.0.0.1 --port 8009

```

先创建账号、配置读写权限和受控环境文件，再由管理员安装服务；查看日志用 `journalctl -u <实际服务名>`。不要把密钥直接填入公开 unit 示例。Windows 长期托管同样应固定解释器、根目录、参数和日志，设置一个实例运行，不使用可见窗口反复启动副本。

## 10. 反向代理、认证与网络

当前更适合受控本机或内部试用。助手没有完整登录与 sid 所有权检查，编辑器登录不会覆盖 `/assistant/api/*`。对其他人开放时，应先在入口部署组织认可的认证/授权和 HTTPS，限制模型、MySQL、ADP 连接范围；真正多用户隔离仍需要应用改造，不能只靠随机 sid。

反向代理建议保留完整路径，避免把 `/assistant/` 错重写成编辑器根路径。前端有根绝对 URL，未经改造不直接挂到 `/workbench/` 之类额外子目录。

下面是 Nginx location 示例，**不包含完整认证、证书和生产限流配置**：

```nginx
location / {
    proxy_pass http://127.0.0.1:8009;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 900s;
    client_max_body_size 21m;
}
```

关闭缓冲保障 SSE 及时送达；上传代理上限需给 multipart 留开销，同时应用仍执行 20MiB 单文件上限。代理超时应结合任务期限设置，不能靠无限延长掩盖模型或工具故障。代理后的 HTTPS、Cookie、来源和前缀需实测。

当前保持 **一个 worker、一个实例**。增加 workers 会使编辑器内存登录、助手任务和 SSE 订阅落到不同进程；多实例还需要会话路由、共享状态、权限隔离、取消传播和事件恢复设计。

## 11. Docker 的现状

根目录目前没有合并版 Dockerfile/Compose。`rule_editor_new/Dockerfile` 与 `docker-compose.yml` 只部署编辑器，使用 Python 3.11、8010 映射，不包含助手、Node 和合并生命周期。运行它不会得到完整工作台。

需要容器化整个项目时，应单独交付合并镜像：包括兼容 Python 与 Node、根 `merged_app/start.py`、两套业务依赖、数据及受控配置挂载、助手检查点持久卷、非 root 用户和同端口双健康验证。入口仍应通过 `start.py` 设置实际 PORT，SSE 与单实例限制继续保留。此项是后续部署工作，不是已有可照抄的合并容器方案。

## 12. 备份、升级与回退

升级前记录代码版本/包快照、Python/Node 版本、依赖、当前模型选择、业务数据版本及配置变更。至少备份两套配置、源 BOM、编辑器索引/方法注册表、助手 BOM、需要保留的 LangGraph 历史。

SQLite 建议在服务停止且连接关闭后备份；如在线备份，应使用一致性备份机制，不在活动连接期间删除 WAL/SHM，也不只拷一个可能未 checkpoint 的主文件。备份含业务文本与敏感配置，需受控保存。

推荐升级顺序：

1. 另存完整配置和数据备份；导出浏览器中未保存的规则。
2. 在隔离目录安装/验证新代码和依赖，模型、数据库评测与正常用户历史隔离。
3. 跑相关离线回归；需要真实验收时先明确环境。
4. 停止已确认的旧实例，切换代码与配套数据，再启动统一入口。
5. 验证两页、认证、候选、生成、SSE 和外部依赖，确认无持续错误。
6. 失败时停新实例，恢复成套代码/配置/数据并重启，不混用旧程序与新 schema。

服务回退不等于恢复浏览器 localStorage。历史 `stable-20261029` 仅作对照，未经核对不覆盖用户当前配置、模型或检查点。

## 13. 排障速查与交接验收

| 问题 | 处理重点 |
| --- | --- |
| `No module named backend` / `rule_editor` | 用根目录 `start.py`；检查 cwd 和实际解释器，不在 Scripts/web 目录猜导入 |
| `Missing project` / 缺依赖 | 看启动脚本实际选中的 Python；新电脑重建环境，使用该解释器安装 |
| `node` 未找到或没有 `node:sqlite` | 检查 Node 版本、进程 PATH、`AGENT_NODE`，不能仅看交互终端 PATH |
| 8009 占用 | 核对监听 PID、命令和路径，停止正确实例或改端口，不批量杀 Python |
| 401 / 登录失败 | 本地账号是否已配置、重启后 Cookie 是否失效、请求是否带 Cookie |
| health 正常但模型失败 | 配置/环境覆盖、模型地址、认证、协议、流式工具支持和诊断日志 |
| 助手编译复核不可用 | profile 是否存在、PORT 是否一致、编辑器登录和本地回环可达 |
| 规则查询无结果 | 先区分模型范围/关键词未命中与连接失败，不自动切 BOM |
| SSE 不出字/一直忙 | `/assistant` 前缀、代理缓冲、连接、结束事件及任务状态 |
| 换 BOM 后候选/生成不一致 | 编辑器 ETL、源模型、注册表；助手库与规则范围需另核对 |

交接完成应能做到：新电脑按本文启动两页；理解两套配置与数据；运行离线回归；定位一条规则从输入到标注/生成，以及一个问题从 prompt 到模型/工具/SSE 的调用链；知道哪些验收仍需真实模型、业务数据库和 ADP 授权环境。不要仅以“首页打开了”作为接手完成标准。
