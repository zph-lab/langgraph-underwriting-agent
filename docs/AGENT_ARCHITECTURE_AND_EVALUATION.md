# Agent 架构、技术与评测说明

本文补充仓库首页，明确开发贡献与技术证据。个人开发重心为 LangGraph Agent 及其工程化和集成；公司已有规则文档编辑器提供规则编辑、校验、转换及平台上传能力，相关核心能力不归为个人原创。

| 范围 | 内容 | 代码入口 |

## MCP 接入与当前调用方式

项目使用 MCP Python SDK 的 FastMCP 暴露两个工具：

- `bom_search`：按关键词检索 BOM 字段与方法，可指定数量、类型及是否包含方法。
- `rule_search`：在配置范围内检索已有规则，返回规则展示及结构化信息。

服务使用 stdio，由外部 MCP 客户端启动和管理。在 Agent 业务目录、已安装依赖的 Python 环境中运行：

```powershell
python -m mcp_service.server
```

MCP 服务与 Web Agent 共享检索核心。目前 Web 会话直接调用共享检索实现，尚未使用 MCP Client 建连、工具发现与协议调用。因此对外可以表述为“实现 BOM / 规则检索的 MCP 服务封装，支持标准 MCP 客户端复用”，当前架构图应保留 Web 与 MCP 两条接入路径。

将 Web 默认链路切换为 MCP 属于后续运行层改造，需要同时验证子进程生命周期、取消传播、超时、错误语义与事件兼容；本次介绍优化未改变运行时调用行为。

## 工程设计的价值

LangGraph 将模型生成与检索组织为有状态循环；BOM 和已有规则为业务回答提供可审核依据。提示词与领域 Skills 约束四段式交付，有限交付检查可拦截缺少必要结构的答复，但不能证明业务语义全部正确。

上下文优化使用专用模型输入视图消除重复文本，保留原始检查点与工具事件；同轮重复结果用引用表示，并通过预算及检索收敛限制循环。这样既能测量输入与调用开销，也保留问题追溯所需证据。

统一工作台复用公司编辑器的既有能力。Agent 提供规则辅助生成、校验适配及工作区切换，用户负责后续审核、粘贴及上传。该集成未实现自动发布闭环。

## 如何评价效果

机制正确性、业务质量与性能分别报告。测试通过不能替代真实模型业务评测；检索成功不能替代字段映射正确；格式通过不能替代条件与动作等价。

业务集覆盖检索、展示、BOM、规则编写、文档转写、澄清和无结果，按来源分组避免近重复泄漏。固定输入只向模型发送任务，参考答案保留在评分侧；重复运行并保留失败和超时，人工复核比较符、金额、日期边界、前导零、对象路径与动作参数。

性能比较记录模型调用、工具请求、实际 Token usage 和总耗时，区分任务完成与观察窗口截断。证据回放采用同一工具结果与 tokenizer；真实配对保持输入一致。现有数据可支持具体输入缩减和单案例时延改善，不能支持总体质量、线上吞吐或稳定完成率的提升结论。
