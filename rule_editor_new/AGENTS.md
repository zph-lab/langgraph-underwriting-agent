## 1. 项目定位与术语

这是面向保险业务的 ADP 规则文本编辑器，当前主流程是 v2：自由文本编辑、基于业务模型的候选补全和校验、生成规则 JSON、提交到外部 ADP、离线条件命中测试。

- **BOM（Business Object Model，业务对象模型）**：业务词典和数据说明书，定义对象、字段、类型、枚举、方法与参数。例如定义“投保人有数字类型的年龄字段”，不保存“张三今年 65 岁”这类实际业务数据。
- **ADP**：本项目连接的外部决策规则平台，提供规则保存、预定义、动作定义和规则测试等接口。本仓库未明确其英文全称，不自行推断。
- **规则文本 / desc**：用户编写的中文规则，包含“预定义 / 如果 / 那么 / 否则”等内容。
- **fieldPath**：中文业务路径对应的底层路径，如 `appbase.someField`。
- **ruleContent**：中文条件转换得到的 ADP 条件树 JSON。
- **方法注册表**：将 BOM 方法映射到 ADP 真实 `expressionId` 等元数据的 JSON 文件。
- **ETL**：把 BOM 等源数据转换为 SQLite 查询索引的过程，会重建数据产物。

示例：“年龄大于 60 岁就人工审核”。BOM 定义年龄和审核动作；编辑器帮助编写、校验、转换；ADP 保存规则并结合实际投保数据执行判断。本地求值器用于条件验证，不是完整 ADP 引擎。

当前主流程不依赖大模型。`llm.enabled=false`、`search.use_semantic=false`；`llm/`、`rag/` 中的扩展代码及部分检索配置不代表已接入实际编辑流程。

## 3. 必须保持的行为与约定

### 编辑、校验、生成


- BOM 方法返回对象的带参子字段（如 `保单的险别0, 险别(动态域集的险别代码的第三者责任险)的保额/限额(元)`）由 `desc_to_rulecontent/parameterized_paths.py` 共用识别，保持完整字段及叶子类型；生成时保留 `exprNode.paramValue`。逗号后空格及中英文括号兼容，非法参数或子字段仍须拦截。回归：`python -B -m unittest rule_test.test_parameterized_paths -v`（读取当前配套车险 BOM/SQLite）。修改运行时逻辑后需重启，无需重建 ETL。

- 字典选择支持 `属于（单选）`、`属于（多选）`、`不属于（单选）`、`不属于（多选）`，兼容英文括号。单选填一项，多选用 `[项1,项2]`；取值限于字段 `codeService` 对应的 BOM 动态域，缺字典或非法值阻止生成，不回退全局同名项。共享映射位于 `desc_to_rulecontent/selector_values.py`，`GET /api/selector_context` 提供当前值区间及选项；`car…Service` 兼容无 car 前缀的动态域类名。此功能使用源 BOM，无需重建 ETL；修改 BOM 后需重启清除缓存。保留旧“属于…中的一个”语法。

- 编辑器以自由文本为主，候选辅助输入；实际字段、方法和类型来自业务模型，避免为某一业务模型硬编码字段或目录名。
- `/api/annotate` 与生成前的 `_validate_rule_text` 应维持一致的校验口径。修改语法时同时检查候选、预览、生成三个阶段。
- 预定义别名要在规则行校验和生成时正确注入；保留跨行引用、类型判断及重复别名检查。
- 条件解析中，同层“并且/或者”按文本顺序左结合，不套用其他语言的 AND 优先级。复杂逻辑用英文 `()` 明确分组；不要无意改变已有规则含义。
- 条件算术候选及输出采用中文“加/减/乘/除”，兼容输入符号的现有行为；预定义表达式有独立解析路径，修改时分别核对。
- 区间候选采用“在 起值 和 止值 之间”，按字段类型生成对应运算符；保留已有旧语法兼容，未填占位或残缺区间应阻止生成。
- 修改运算符时检查候选兼容表、标注、转换、本地求值和旧辅助模块的引用，防止只支持其中一个阶段。

### 生成与上传

- `POST /api/generate_rule` 是离线生成，不访问 ADP，不需要 ADP token。
- `POST /api/upload_generated` 上传已生成的结构，不重新生成。前端生成后文本或关联参数变化时，应要求重新生成；后端以传入 generated 为准，前端指纹不是后端安全校验。
- `POST /api/upload_rule` 是兼容的一键入口，调整共享逻辑时同时检查它。
- **BOM 决定方法入口、文案、参数结构；`rule_model.txt` 决定真实 `expressionId`。** 不用类名与方法名的派生字符串冒充平台 ID。
- 保留同名重载、方法文案归一化和已有脏数据匹配逻辑，改变匹配策略时验证真实动作实例。
- 上传会分别保存预定义、规则和动作，多次 HTTP 请求没有统一回滚；失败可能已经部分保存。错误反馈要说明失败阶段。
- 上传默认可能根据已有 `ruleId` 查询并覆盖更新。任务未涉及 ADP 写入时，使用离线生成、本地测试或 mock 验证；需要真实写入时先明确目标环境和规则编号，并遵循用户已有授权范围。

## 4. 数据配套与换模型

一套可运行的模型至少涉及：

1. `data.bom_path` 指定的 BOM。
2. 与 BOM 对应的 ADP `rule_model.txt`。
3. 由它们生成的方法注册表。
4. 由当前 BOM 重建的 `data/bom_catalog.sqlite`。
5. `repository_file`、`catalogue_file` 提供的库与分类列表。
6. 上传目标、`bom_base_info_id`、`bom_model_id` 及目标库之间的匹配关系。

默认方法注册表由 `default_methods_registry()` 按 **`samples_dir` 末级目录名**选择 `bom_methods_<目录名>.json`，不是按 `bom_path` 文件名选择；找不到可能回退 `bom_methods_非车.json`。排查动作问题时先核对实际加载文件。

换模型时先检查现有工作区和备份需要保留的数据，确认目标模型后修改配套配置，生成匹配注册表、重建 ETL、重启服务，再验证字段、方法、生成 JSON 与本地测试。不要仅替换 BOM 就宣称换库完成。

```powershell
# 以下会写入/重建产物；先确定目标模型和输出位置。
python desc_to_rulecontent/write_rule_to_adp.py --gen-methods-model "<模型目录>/bom.json" --model-methods "<模型目录>/rule_model.txt" --gen-methods-out "desc_to_rulecontent/bom_methods_<模型目录名>.json"
python -m rule_editor.etl.run_etl

# 仅刷新决策库和分类表时，不必重跑整个 ETL。
python -m rule_editor.etl.repositories
```

新增候选运算符通常需要重跑 ETL；仅修改运行时转换逻辑通常需要重启服务。配置、模型和注册表有内存缓存，不能假定改文件立即生效。库与分类接口现查数据库，单独更新列表通常无需重启。

`respository_cata.txt` 是现有真实文件名，拼写虽不规范，也不要只改文件名而遗漏配置和调用方。

### 规则误判的默认处理流程

后续经常会收到“规则正确但字段标红”“候选能选但生成失败”等问题，应按以下流程修复，不把取消校验当作解决办法。

1. **还原输入与预期。** 从截图或用户原文提取完整规则及预定义上下文，保留空格、逗号、中英文括号、日期时间、引号和连接词。截图中无法辨认且会影响语义的内容再向用户确认，不擅自改写业务规则来迎合解析器。
2. **核对当前数据。** 检查实际 `bom_path`、SQLite 与方法注册表；找到相应 BOM 节点，核对 `label`、`fieldPath`、叶子 `type`、父对象、方法参数及动态域。字段名包含数字、逗号、空格、斜杠或括号，并不意味着字段非法。源 BOM 正确而运行时不认识时，先排查路径构建和分词；发现数据不配套则说明证据，不用修改数据库记录掩盖问题。
3. **建立最小复现。** 同时保存原始失败规则和最小失败条件，记录 `_segment_words` 的分词、`annotate` 中 `valid=False` 的词与错误信息，以及 `RuleGenerator.generate` 的结果或异常。`annotate` 面向规则行；完整多段规则应走 API 的 `_annotate_text` 分流，不能把整段文本直接传入单行路径后据此认定页面有误。
4. **沿实际调用链定位。** 顺序检查 `_build_path_index` → `_segment_words` → `_find_path_item` / `_annotate_word` → 类型、相邻词、括号校验，再核对 `RuleGenerator._longest_label`、参数解析和 JSON 构建。粘贴后才出错时，检查 `normalize_pasted_rule` / `_norm_if_line`；后端正确但页面仍红时，再检查前端请求、着色与服务缓存。
5. **修复共同原因。** 优先补齐由 BOM 驱动的识别能力，让预览与生成共用匹配规则；复用现有归一化和参数解析。不得按截图里的险种、字段名、金额或模型目录写特判；不得通过统一返回 `valid=True`、跳过类型校验或把未知路径全当字符串来消除红色。
6. **检查语义而不只检查颜色。** 合法字段应保持正确的叶子类型和 `fieldPath`。带参字段必须保留所选参数的节点、类型及 `exprNode.paramValue`，不能只生成空参数骨架。不同险别对应的参数不能在复用解析器或缓存时串用；金额、比较方向、算术及括号分组含义必须保持一致。
7. **补充并运行相关回归。** 先让原始规则与最小复现通过，再检查相邻语法和非法反例。已有回归按改动范围运行；无关功能不大范围重写。真实 BOM 用例用于验证当前配套模型，通用语法优先用临时 BOM/SQLite 构造，避免污染业务数据。
8. **交付与生效。** 说明根因、改动范围、实际运行的测试及未覆盖项。涉及内存缓存时说明重启；只有数据索引确需变化才重建 ETL。未做浏览器或 ADP 联调就明确说明，不把离线测试通过等同于平台执行完全一致。

### 误判修复的回归覆盖

每个语义修复都应覆盖“合法规则恢复通过”和“非法规则继续被拦截”。根据受影响语法选择以下场景：

| 场景 | 核验重点 |
|---|---|
| 用户原例与最小条件 | 标注通过、生成通过、JSON 字段及参数正确 |
| 标点与空白 | 逗号后有/无空格、中英文括号、参数值自身含括号；不拆坏真实字段名 |
| 带参对象子字段 | 叶子类型准确；不同参数不串用；未知参数、错误类型、缺括号、未知子字段被拦截 |
| 条件组合 | 单条件、并且/或者、括号分组、算术比较；左结合与边界值保持原语义 |
| 粘贴与编辑 | 粘连文案整理后合法；直接输入与粘贴后的结果一致 |
| 预定义与字典 | 涉及时验证别名跨行引用、同元素绑定、动态域隔离及单选/多选 |
| 前端与接口 | 涉及时验证候选、预览、生成前校验一致；生成后修改仍要求重新生成 |

不要声称当前通用匹配器已覆盖所有对象方法语法：`ParameterizedPaths` 当前只处理标签中恰有一个 `()` 的方法子字段模板，未实现任意多级嵌套方法调用。扩展到多槽、重载或更多类型前，先核对当前实现并补充对应回归。

现有离线回归不依赖 pytest：

```powershell

```

本次规则误判修复后的相关离线回归集合：


按改动选择验证，避免无关的大范围重建：

| 改动 | 最低相关验证 |
|---|---|
| 候选或标注 | 实际模型中正常、非法、边界输入；候选与预览一致 |
| 条件解析或运算符 | 中文输入 → JSON 结构 → 本地正反例；核对逻辑和类型 |
| 预定义 | 别名解析、跨行引用、列表同元素绑定、缺失/重复别名 |
| 动作转换 | 当前 BOM 的真实方法、重载、参数类型和 expressionId |
| 上传编排 | 使用 mock 检查请求与失败阶段；生成结果保持一致 |
| 前端交互 | 页面编辑、候选定位、生成后修改拦截、草稿恢复 |
| 助手导航或布局 | 原端口/hash 不丢失、全屏无重复布局、返回按钮、文本保留、iframe 复用、浏览器返回与窄屏可用 |
| 模型切换 | BOM 与数据库一致、注册表配套、库/分类与 ADP 模型 ID 核对 |
| Docker | 构建、监听、映射、健康检查与实际业务接口 |

为会改变业务语义的修复补充有意义的回归用例；简单文档和低影响样式改动不要求新增测试。验证失败先区分代码问题、缺依赖和外部服务不可达。不要为了通过本地检查连接真实 ADP 写规则。

## 7. 登录、凭据与集成边界

- 编辑器本地登录与 ADP token 是两套机制，不能相互替代。
- 本地会话存于进程内存，用 HttpOnly Cookie 承载；重启失效，多 worker/多实例不共享。扩容前需重新设计会话存储。
- ADP token 支持配置预填、用户输入、URL 参数和父页面 postMessage 注入；维护时保留现有优先级与刷新行为。
- 登录账号、密码从 `config.yaml` 的 `login` 段读取；账号密码均为空时会拒绝所有登录。配置有内存缓存，修改后需重启并重新登录。登录失败时先检查配置是否已填写、当前进程是否加载新配置、Cookie 与接口响应，不直接认定规则修复改坏了登录。
- 用户已经配置的本地账号密码必须保留。规则解析、标注、候选等修复不得顺手清空账号、禁用登录或替换 ADP token；只有用户明确要求更改配置时才调整对应项。
- 配置可能含明文账号密码及 ADP token。不要把凭据复制进本文件、其他文档、日志、测试样例或最终回复；新增配置示例使用占位符。排查只报告是否配置及验证是否成功，不输出整个含凭据配置。提交或共享前检查配置差异，避免把本机凭据一并提交。
- 前后端默认同源，不为解决普通集成问题直接开放任意来源 CORS。
- iframe 的消息来源检查、Cookie 行为与部署域名有关，修改嵌入方式时检查实际调用代码，不以注释代替验证。
