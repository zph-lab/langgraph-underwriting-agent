# desc 转 ruleContent 并上传 ADP 数据库 — 执行命令说明

本目录包含两件套脚本（纯 Python 标准库，无需 pip 安装第三方包）：

| 文件 | 作用 |
|------|------|
| `rule_desc_to_content.py` | 把中文 `ruleDesc` + `bom.json` 解析成平台 `ruleContent`(JSON)。 |
| `write_rule_to_adp.py` | 把 `ruleContent` 通过 ADP「保存如果」接口写入决策库（含 RSA 登录、预定义 PUT、那么/否则 POST、回读验证）。 |

> 依赖关系：`write_rule_to_adp.py` 在运行时会 `import rule_desc_to_content`，
> **两个文件必须放在同一目录**。`rule_desc_to_content.py` 本身只用标准库，可独立运行。

---

## 前置准备

1. 准备 BOM 文件，例如：
   `D:\deskface\艾融科技项目文件\intelligent_Rule_Editor\非车销售\bom.json`
2. （可选）准备 predefine 预定义文件 `predefine.json`，内容格式：
   ```json
   [
     {"content": "指定'当前险别'为一个来自(in) '保单'的人身险信息的060032学生平安保险(2009版)B款险别列表"}
   ]
   ```
   > 注意：`来自(in)` 必须放在根对象（如 `保单`）**之前**，否则脚本正则匹配会错位。

---

## 方式一：仅生成 ruleContent（不连数据库，先验证正确性）

```cmd
cd /d "D:\deskface\艾融科技项目文件\desc_to_rulecontent"

python rule_desc_to_content.py ^
  --bom "D:\deskface\艾融科技项目文件\intelligent_Rule_Editor\非车销售\bom.json" ^
  --desc "规则预定义变量的当前险别的学生类别 是 动态域集的学生类别的幼儿园 并且 保单的个团标志 是 动态域集的个团标志的团单 并且 保单的费用政策渠道 属于 动态域集的费用政策渠道的直销及其他 中的一个" ^
  --predefine "predefine.json"
```

- 输出：直接打印 ruleContent JSON 到屏幕。
- 也可用 `--out result.json` 把结果落盘，供方式二读取。

## 方式二：一步到位（desc + BOM 直接生成并上传 ADP）

```cmd
cd /d "D:\deskface\艾融科技项目文件\desc_to_rulecontent"

python write_rule_to_adp.py ^
  --url http://192.168.0.205:8902/decision/rule ^
  --bom "D:\deskface\艾融科技项目文件\intelligent_Rule_Editor\非车销售\bom.json" ^
  --desc "规则预定义变量的当前险别的学生类别 是 动态域集的学生类别的幼儿园 并且 保单的个团标志 是 动态域集的个团标志的团单 并且 保单的费用政策渠道 属于 动态域集的费用政策渠道的直销及其他 中的一个" ^
  --predefine-content-file "predefine.json" ^
  --with-predefine ^
  --bom-base-info-id <你的bomBaseInfoId> ^
  --rule-id TEST_001 ^
  --rule-name "测试规则" ^
  --path /调节 ^
  --repository-id 15fed48c97604299a7d7cf3f8e425b1a ^
  --catalogue-id b6a9d546d48948ae90e74c2730584bdf ^
  --verify
```

> 不传 `--token` 时会用默认账号 `<账号>/<密码>` 自动登录（RSA 加密密码流程）。
> 若已有 token，加 `--token <adp-token>` 可跳过登录。

## 重要注意事项（踩坑记录）

1. **务必用 `cmd`，不要用 PowerShell。**
   PowerShell 会把路径/文本里的半角括号 `(in)` 当成语法，报 `表达式中缺少右“)”`；
   且中文路径在 PowerShell 里容易编码错乱导致 `文件不存在`。
2. **`--predefine` / `--predefine-content-file` 传的是文件路径，不是文本本身。**
3. **predefine 文本里 `来自(in)` 顺序**：`指定'别名'为一个来自(in) '根对象'的...`（in 在前，根对象在后）。
4. 不同规则库用不同 `repository-id` / `catalogue-id` / `path`，见脚本顶部注释里的车险 / 非车核保对照表。

## 验证

- 方式二/三加 `--verify` 会自动 GET 回读刚写入的规则，看到 `success:true` 即成功。
- 方式一可先本地确认 ruleContent 结构正确，再走方式二/三上传。
