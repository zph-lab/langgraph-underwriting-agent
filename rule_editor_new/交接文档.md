## 一、项目是什么

基于 ilog 规则引擎 + BOM 业务对象模型的**自由文本规则编辑器（v2）**：用户像写自然语言一样直接输入规则文本，系统按**空格分隔的语义单元**智能补全候选 + 合法性校验；最终文本即规则本身（上传时才转 ruleContent）。

```
预定义
指定'当前险别'为一个 063048xxx标的信息 来自(in) '保单'的人身险信息的063048xxx险别列表
如果 保单的个团标志 是 动态域集的个团标志的团单
那么 设置061002人身意外伤害保险险别代码为12749
```

- 按**空格**进入新词槽位，按**上一词类型**智能弹候选；输入文字按光标所在词检索 BOM 多级路径
- 候选只是提示，可不选、自由输入、随时修改
- **预览区**按词着色 + 合法性校验（编辑区 textarea 纯文本无法着色）
- 三类句式：**规则句**（如果…）、**预定义句**（`预定义 指定'别名'为…`，给列表/字段/方法结果/表达式起别名）、**动作句**（那么/否则，回写方法调用）；多行混合，入口词可独立成行
- 预定义解析成功后，规则行可直接引用 `规则预定义变量的<别名>的<子字段>`
- v1 状态机文件（statemachine/suggest/desc_codec/validator）保留未删，**不参与主流程**

## 二、核心原则（务必理解）

1. **规则 = 自由文本，候选 = 检索提示**。候选不约束输入，两个空格之间的文本参与一次检索。
2. **BOM 处理核心**：把 BOM 所有**多级对象路径**（任意深度）提取为检索表，label 用"的"连接（`保单`、`保单的个团标志`…）；**不做过滤**（含 `()` 方法节点、含括号字段全部纳入）。条数量级随 BOM 表（当前 新车险915 约 1.6 万节点全量入索引）。
3. **`field_path` 统一接地**：样本与 bom.json 的 `fieldId` 不一致但 `field_path` 完全一致，每条检索项带 `field_path` 供回灌/校验接地。
4. **每个词（空格间文段）有类型**（keyword/connector/operator/field/object/number/boolean/value），是候选、着色、校验的共同基础。
5. **规则样本不参与候选排序**（v2 基于结构检索）；样本仅用于评估/回放（见待办）与预定义形态统计。

## 五、核心 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/search?word=&prev=&prevprev=&limit=&predefines=` | 词检索。`word` 空→按 `prev`/`prevprev` 智能候选（prev 运算符→值；prev 字段→兼容运算符；prev 运算符/连接词/如果→一级对象，含预定义一级 `规则预定义变量`）；`word` 非空→路径+运算符/连接词。`predefines`=编辑区预定义行（`\n` 分隔），解析成功后注入预定义词条 |
| GET | `/api/predefine_search?kind=type\|path\|cond_field\|cond_op\|field_path&word=&limit=&type_name=&field=` | 预定义主句候选。type=list 元素类型 / 列表路径 / 条件字段 / 条件运算符 / 非列表对象字段路径。策略与 /search 一致（完全>前缀>包含），另有 n-gram 模糊兜底与方法子序列兜底（见"七·检索"） |

| GET | `/api/method_search?word=` | then/else BOM 方法候选，带 `template` 占位模板（expressionArray 渲染，畸形条目回退 BOM label 槽位重建） |

| GET | `/api/desc?text=` · `/api/health` · `/api/boot_id` | 回显 · 健康检查 · **进程指纹**（前端缓存作废比对用，见 12.3） |

## 六、交互模型（多模式 + 自由文本 + 空格词检索 + 智能候选）

前端为**单个 `<textarea>` 编辑区** + 跟随光标的候选下拉 + **预览区着色/校验**（编辑区纯文本无法着色）。`app.js` 维护多模式：

| 模式 | 进入方式 | 行为 |
|---|---|---|
| `entry` 入口 | 初始 / 回车换行后 | 只弹 `预定义`/`如果`/`那么`/`否则` 四个引导候选（不走后端） |
| `rule` 规则 | 选/输入 `如果` | 词检索 + 校验 + 着色 |
| `predefine` 预定义 | 选/输入 `预定义`（→再选`指定`）/ 旧格式直接 `指定` | 预定义句多步引导 |
| `then` / `else` | 选/输入 `那么` / `否则` | 动作方法编辑（方法名→参数位两阶段） |

### 模式判定与兜底（关键）

- **词级兜底**：`refresh()` 全局检测——光标所在词是 `指定`/`预定义`→predefine、`如果`→rule、`那么`/`否则`→then/else，粘贴/手输导致内容与模式不一致时自动纠正。
- **行级对齐 `modeForLine`**：模式是全局状态，光标点回其他行时必须按**光标行归属的引导词块**重推模式（与 `foldEntryLines` 折叠归属一致）：当前行行首引导词→对应模式；正文行/空行向上找最近孤立引导词行（空行视作上方正文块的排版延续，穿到顶部未找到→null 保持现模式——**空行绝不回退 entry**，否则预览整段退化纯文本）。`refresh()` 开头 `lm !== mode → enterMode(lm)`。
- **冒号兼容 `stripLeadColon`**：手输"预定义：/如果：/那么：/否则："（全/半角、可连多个）在全部识别点归一为"引导词+空格"标准形态（仅识别侧，候选不动）；正文内冒号（如"符合条件："）不受影响。
- **enterMode 补空格**：进入新模式时给引导词补空格，条件必须含"行首到光标仅引导词"检查，防止光标在正文中间误拆正文。

### 入口词独立成行

候选选 `如果/那么/否则/预定义` 后自动换行——引导词独占一行，正文续行。旧式同行写法完全保留：

- `foldEntryLines`：预览标注/上传/复制/预定义词条收集前把"引导词行+后续行"折回单行逻辑句，**后端始终只收单行**，两写法结果逐字节一致。
- 预定义两行式：上一行孤立 `预定义` + 本空行 → 弹 `指定` 候选（`prevLineText`），选中后 `pdstart` 在空行补 `指定''`（光标进别名引号）。
- **预览区**渲染时引导词段再拆独立一行展示（`renderEntryLine` 按字符拆点，token 内拆段产生同类型双 token），引导词统一**黑色、加粗 700、字号 1.2em**（`styleLeadNodes`），正文类型着色不变；`lineBuf`/`renderedPlainLines` 仍按逻辑行累计，上传文本不受展示拆行影响。
- **候选下拉跟随光标**（IDE 式）：镜像层测 textarea 光标像素位置（`caretOffset`），候选弹在光标行正下方（放不下翻上/左移）；`position:fixed`，滚动/缩放防抖重定位。
- **光标在词中间选候选 = 整词替换**：预定义右值各分支经 `pdRvalueSpan`（主句前缀锚定，替换区间=前缀末尾→行尾或 `;` 子句分隔符）；通用分支按空格分词、then/else 参数位按后端 `start/end` 区间整段替换。**注意**：成形右值（含闭合引号、路径内含空格）必须走区间替换，否则正则失配会"点候选没反应"或主句被方法模板吞掉。

### 规则模式（如果）

1. 空格进入新词槽位，按上一词类型弹候选：prev 运算符→按字段类型给值（数值/日期自由输入）；prev 字段→兼容运算符；prev 运算符/连接词/如果→一级对象。
2. 输入文字按光标所在词（两空格间文段）检索多级路径；点/Enter 候选替换当前词，选中对象继续弹下一级。
3. 填入后仍是普通文本可随意改。
4. **算术运算符（2026-09-24）**：数值比较支持四则运算链（`字段 大于 保额 减 免赔额`、`金额 加 100`、两侧算术 `_parse_left_arith`）。独立词类 `arith` 检索/标注/校验三端共用（`textsearch.py` 的 `ARITH_CANDIDATES/ARITH_WORDS/ARITH_NORMALIZE`），预览标紫（#6c5ce7）。**词形口径：候选、desc 规范文本、ruleContent 产物 label/desc 一律中文 加/减/乘/除**（code 恒为 ADD/SUB/MULTIPLY/DIVIDE）；符号 `+ - * /` 与全角 `＋－＊／×÷`（×÷ 归 */）是手输兼容别名——输入符号命中同一中文候选、标注同样标紫，上传时生成端经 `ARITH_CN` 词形归一输出中文。运算符须两侧留空白（生成端 `_find_arith_op` 防日期/比值串/`保额/限额(元)` 误切；前端候选插入自动补前后空格，手输粘连形标红提示）。**例外：预定义子句右值维持符号口径**（`_PD_ARITH_OPS` 只认 `+ - * /`——预定义行整行直发 ADP 解析，中文运算符词形不被接受，该场景手输中文标红属预期）。
5. **区间运算符（2026-09-24，词形对齐 运算符924.txt）**：数值/日期/时间字段运算符候选为 `在...和...之间`（不再弹"介于"；旧词形 `介于 起,止` 仍解析兼容但不作候选）。前端选中候选时**所有 `...` 占位一次替换为空格值位**（app.js `split("...").join("   ")`，插入 `在   和   之间`，光标落首个值位），随后按 起值→`和`→止值→`之间` 逐步引导，校验状态机见"八·2"。

### 预定义模式（预定义 指定…）

列表模板（剥 `预定义 ` 前缀后）：`指定'别名'为一个 X来自(in) 'root'的路径`；非列表：`指定'别名'为'root'的字段路径`（别名闭合后弹 `为一个`[列表]/`为`[非列表] 二选一）。上传**剥离 "预定义 " 前缀**（predefineContent 以 `指定'` 开头，兼容 ADP；旧无前缀格式全兼容）。"为一个"后与"来自(in)"后的编辑辅助空格由 `normalizePredefine` 在生成时清理。

- 列表四步：别名（引号间无候选）→ 元素类型（`kind=type`）→ `来自(in)` → 列表路径（`kind=path`）。
- 非列表：`为` 后弹对象/叶子字段路径候选（`kind=field_path`）；路径在"符合条件"/`;` 处截断，多余空格尾巴按最长可命中前缀剥离灰显。词条注入后 `规则预定义变量的<别名>` 为 field（type=字段类型）。
- **"符合条件"子句**（列表可选尾段，与主句同行）：`… 符合条件：当前这个 <类型名>的<字段><运算符>"<值>" ;`，语义 `list.where(item => item.字段 == 值)`。五段式引导（主句完整+尾空格→弹 `符合条件：`；自动补 `当前这个 `→类型名固定一项→补 `X的`→条件字段 `kind=cond_field`→字段选中立即弹运算符 `kind=cond_op`（按字段类型）→值自由输入）。正则防灾难性回溯：路径段一律 `\S+(?:\s+(?!符合条件)\S+)*`。
- **右值四形态**（解析收口见"八 · 7"）：①对象字段路径（root 引号可省）②方法调用（可带上级对象"的"链）③字面常量 ④算术表达式（嵌套方法/括号/四则，词法器逐 token 当场校验）。
- **预定义变量引用（规则模式三级候选）**：预定义行解析成功后注入——一级 `规则预定义变量`（固定名）→ 二级 `规则预定义变量的<别名>`（object=列表/field=非列表）→ 三级 `…的<子字段>`（来自所引列表节点 BOM 子节点）；fieldPath=`规则预定义变量.<别名>.<字段>` 与生成端口径一致。无任何解析成功行时不注入。中文弯引号归一为半角。前端 `predefineLines()` 随 /search、/annotate 发送 `predefines` 参数。

### 那么/否则（then/else）动作模式

- **方法候选**（`/api/method_search`）：方法索引取 `BomCatalog.methods`（field_path 以 `()` 结尾全量收集，含重载不去重）；候选带占位 `template`——expressionArray 的 text 原样 + input 参数位占位（desc 有语义→保留；字段引用→原样作默认值；通用/超长→`<returnType>`）。插入后光标选中首个占位符，**Tab 跳下一占位符**。畸形条目（text 段含裸数字槽位）按 BOM label 槽位重建模板（`degenerate_label_template`）。
- **参数位检索**（`/api/method_param_context`）：注册表 expressionArray text/input 结构切参数值区间；field/text 判据=`codeService` 非空或 desc 无尖括号路径提示（不依赖具体 BOM 名，换表复用）；field 位弹路径候选，text 位不弹；光标在 `<占位符>` 内视为未开始输入。
- **行标注**（`annotate_then_else_line`）：方法匹配（行首去引导词最长前缀命中模板引导段，失败整行红"未匹配到 BOM 方法"）+ 参数空检查（trim 空→红"参数 paramX 为空"）；**占位符与值类型一律不拦**（当字面量上传，与转换器同口径）。合法行分段着色：模板固定文本绿（methodtext）、参数值段灰。
- **上传转换**（`convert_then_else_text`→ADP `{nodeType:"EXPRESSION", codeService, expressionId, returnType, paramValue, fieldParsings}` 结构，POST `/rule/method/define`，body 数组，需 `bomModelId`=规则所属模型）：
  - **解析基准统一走 `effective_parse_basis(label, expr_array, details_list)`**：expressionArray 正常优先；畸形/缺失回退 BOM label 槽位切分（`split_template`，param_types 优先 detailsList——`paramId` 与 label 槽位数字一一对应且 type 更权威；label 来源锚点保留标点 `keep_punct`）。
  - **重载消歧 `pick_registry_entry`**：同 derived 前缀命中多条时，先按 detailsList 参数个数过滤，再用 expressionArray text 段与 BOM label 归一化（全半角冒号逗号统一）按序定位打分择优；前缀匹配必须带 `_` 序号边界。
  - **`expressionId` 一律取 `rule_model.txt` 第 3 列 methodId**（注册表生成口径，禁止「类名_field」派生名上传）；BOM 节点 Java 方法名可与模型错位，匹配有 label 归一化兜底档。
  - 参数值：BOM 字段→`fieldParsings` `${fieldPath}`；字面量→**原样透传不加引号**（字段/字面量由 `${}` 形态区分）；表达式→原样+内部字段转 `${}`。

### 上传到 ADP 决策库（两步分离）

「生成上传参数」（`/api/generate_rule`，纯离线核对）→「上传到 ADP」（`/api/upload_generated`，所见即所传）。要点：

- 上传内容取自**预览区渲染文本**（`renderedPlainLines`，与折叠逻辑行一一对应）按行拆分：预定义行剥 `预定义 ` 整行进 `predefineContent`；规则行去 `如果` 进 `ruleDesc`；那么/否则行进 `thenText`/`elseText`。支持"仅传预定义、无规则行"。
- **双文本校验**：前端查 `lastWords` 无 `valid=false`；后端 `ruleDescRaw` 跑 `_annotate_text`（与预览同一分流管线+预定义词条注入）——预览与上传永远同口径。
- **覆盖更新 upsert**：ADP 保存接口按 body `id` 判定新增/更新。`upload_payload` 默认 `overwrite=True`：POST 前 `fetch_existing_rule_id`（`GET /decision/rule/{ruleId}`）查到主键即回填 `body.id` 自动转更新（更新会按本次表单覆盖 path/库/分类）。
- 成功判定后 `_finish_upload` 统一组装：refs 收集 + `testInput` 骨架（失败附 `testInputError`，不影响上传结果）。

## 七、检索匹配实现（`core/textsearch.py`）

### 索引与打分
- 遍历 BOM 所有 object+字段（**不过滤**，含 `()` 方法节点/含括号字段），按 `field_path` 拼"的"连接 label 入 `path_index`；n-gram 1/2/3-gram（权重 1/2/3）倒排兜底。
- `_match_paths` 精确档：label 完全相等 1.0 > 前缀 0.95−0.005×深度 > 节点名匹配 0.8 > 子串 0.6；0 候选时 n-gram 加权命中率打分（阈值 0.20，`source=fuzzy_ngram`）。
- 值位置（prev 运算符）按字段类型给值候选；选运算符阶段（prev 字段）只给运算符/连接词。

### 预定义右值/参数位检索增强
- **模糊兜底 `_pd_fuzzy_fill`**：`kind=field_path` 精确池（完全/前缀/包含）0 候选时，字段路径走 n-gram 倒排召回（结果按层级浅→深、label 短→长重排——深层长 label gram 命中面占便宜，直排会刷屏），方法候选走字符子序列（"帮助取整"→`向下取整` 模板）；混池时方法配额恒限半量，防止通用词被 setter 方法挤满、字段路径永不可见。
- **参数位按声明类型检索（`predefine_param_context`）**：懒建类型桶 `_ensure_pd_type_pools()`（numeric/date/string 分桶，类型未知叶子沉底，label 预转带引号形态）。空词按（类型档, 深度）排序——`<double>` 槽空词候选全为 double 字段；非空词按（匹配档, 类型档, 深度）打分，类型档=与参数声明精确同型 > 同族 > 未知。
- **方法展示形态带上级对象"的"**：候选/模板用 `动态域集的帮助的帮助.取大值(0,1)(<double> , <double>)`（与注册表样本一致，正对 ADP 预定义直发口径）；标注扫描对带/不带"的"两形态均容忍（head 正则每字符后 `(?:\s*的\s*)?`）。方法参数类型懒读 `bom.json` detailsList 按 paramId 数字序。
- `_strip_tail_empty_parens` 只剥结尾 `()`，禁 rstrip（防把签名 `(0,1)` 剥掉）。

### 预定义词条注入（`predefine_lex` / `_set_pd_lex`）
- 每次 `search`/`annotate` 按 `predefines` 参数**重建** `_pd_lex`（用完即弃，不污染主索引）；前端发送的是折叠后逻辑行，后端无需感知换行。
- 检索池 = `path_index + _pd_lex` 叠加打分；`source="predefine"` 供前端标注；BOM 未命中时 `_find_path_item` 兜底查 `_pd_by_label`。

### 语义分词（预览拼接基础）
`_segment_words(text)`：用全部路径 label 集合贪心最长匹配完整 BOM 路径（含内部空格）为一个 token，否则按空格分普通词——预览"删单元间空格但保留路径内空格"的实现前提。

## 八、合法性校验

`annotate()` 逐词标 `type` 并校验，`valid=false` 的词前端标红 + 悬停显示 error。**该管线同时是预览渲染与上传硬校验（`_validate_rule_text`）的唯一口径**——后端新增校验只要把 token 置 `valid=false`+中文 error，预览标红与阻止上传两端自动生效，前端零改动。

### 1. 词类型标注
`type` ∈ {keyword, connector, operator, operator_tail, operator_mid, field, object, number, boolean, value}。歧义：`如果`→keyword；boolean 字段后 `为`→operator、随后 `是/否/成立/不成立`→boolean；`是` 在 string 字段后→operator、在值位置→boolean。

### 2. 值类型校验（`字段 运算符 值` 三段）
数字→double/int/long/big_decimal **及 string（数值型 string 不区分）**；布尔→boolean；日期（正则）→date/datetime/time；字符串/枚举/对象字段值→string、is_enum、对象节点。对象容器不作值类型强校验。

**区间句式「在 起 和 止 之间」（2026-09-24，词形对齐 运算符924.txt）**：区间运算符从单词"介于 起,止"改为三段式，`annotate` 用 `between_phase` 状态机推进（0→4：`在`后须起值→起值后须`和`→`和`后须止值→止值后须`之间`），起/止值各按字段类型走 `_check_value_type`；新词类 `operator_mid`（中段"和"），"之间"复用 `operator_tail`，三者预览同紫。**骨架未填、悬空（`在 5`、缺`之间`）、`和` 误位、`之间` 缺前置一律标红中文报错**——预览与上传硬校验同一管线，自动阻止上传。旧词形 `介于` 保留兼容：`_check_between_value` 拆 `"起,止"`、`_op_code_for_word`/`_is_operator` 均认，求值/上传不受影响。区间值**内部规范形态恒为 `"起,止"`**：`desc_codec.parse_desc` 把新句式归一为 `DATE_BETWEEN + "起,止"`，上传端 `rule_desc_to_content` 正则 `^在\s*(.+?)\s*和\s*(.+?)\s*之间(?=\s|并且|或者|$)`→`kind='between'` 按字段类型自动选 NUM/DATE/TIME_BETWEEN（与旧 `_op_between` 同口径）。**上传端两处兼容（2026-09-24 二轮修复，勿回退）**：① 区间正则**不得用 `$` 锚定**——前端规范文本（renderWords）只在 arith/连接词/括号两侧补空格，区间五 token 粘连成 `在1000和10000之间` 且后接 ` 并且 …` 子句，必须子句边界前瞻并以 `m.end()` 回填游标；② `_parse_left_arith`（算术链 `A + B 在…和…之间`）尾部除 7 个比较符外须匹配区间三段式（及旧 `介于`，经 `_op_between`），返回 `{'kind':'between','field':{'nest','ops'}}`，`_render` between 分支对 nest 字段出 `_nesting_node` param1、区间类型按首项字段推断（与 cmp 分支同口径）；算术链兜底字面量的截断词表含 `在/介于`。生成端 `phrase_grammar` 模板 `{obj}{field} 在 {value} 之间`（value_mode=range，渲染时 `起,止`→`起 和 止`）。**label 全链路统一为"在...和...之间"**（textsearch/suggest/rule_tree/bom_catalog/evaluator 文案；"介于时刻"并入），其中 `field_operators` 表随 `data/bom_catalog.sqlite` 落库——**改后必须重跑 `python -m rule_editor.etl.run_etl` 并重启 8009**。验证：候选/标注新旧词形/悬空标红 API 全过 + 求值器回归 20 例 OK。

### 3. 相邻词语法
不能连续两连接词 / 连续两字段（前词以 `,` 结尾除外）/ 连续两数字；连接词不与运算符相邻；**值不能裸用**（值/数字/布尔前面必须是运算符或处于参数列表上下文）。

### 4. 括号上下文
仅左右空格隔离的独立括号成词（type=paren）；字段/方法名自带括号是 token 文本一部分。`（` 前是方法名→进入参数列表模式（内部允许字段/值/逗号，punct 不做裸值校验）；分组括号内部递归相邻校验；未闭合左括号有专门提示。已知盲区：参数列表 `）` 后直接接"并且/或者"（缺 `为 是`）annotate 放行但生成端报错（见"九"）。

### 5. 预览渲染拼接
token 之间**删除用户人为输入的空格**直接拼接（语义分词保证字段路径内部空格保留在 `w.text`），两类例外两侧保一个空格：连接词（并且/或者——desc 解析端依赖空格界定）与独立括号（连续 `((` 渲染为 `( (`）。

### 6. 上传链路
前端 `lastWords` 预检 + 后端 `ruleDescRaw` 跑 `_annotate_text` 硬校验（与预览同分流管线，注入预定义词条），不合法即拒绝生成/上传。两步接口的"生成"步还前置检查关联 ID（bomBaseInfoId/bomModelId）。细则见"六·上传到 ADP 决策库"。

### 7. 预定义右值统一解析口径（`_pd_rvalue_parts` / `_pd_expr_parse`）

同一句右值曾有 4 处各写一套逻辑互为盲区，现收口为**单一解析口**（标注与词条注册共用），右值四形态：①对象字段路径（**root 引号可省**——BOM label 零单引号，引号是编辑器/ADP 语法加的）②方法调用（含"的"链、ADP 手写单括号与编辑器模板双括号均命中，消费最长优先）③字面常量（也注册词条 is_const）④**算术表达式**。

- **词法器 `_pd_expr_parse`**：BOM 词典驱动贪心切分（路径/别名/嵌套方法/运算符/括号/字面量），返回 `{complex, form, type, refs, issues, tokens}`；简单路径/纯方法 `complex=False` 走旧标注口径零变化。逐 token 着色 `_pd_expr_words`：token 拼接==右值原文（不注入空格）；非法 token 当场标红+title。`finished` 口径：子句写完才判 error，编辑中悬空运算符/未闭合括号仅 warning。类型推断 `_pd_alias_type/_pd_expr_type`（numeric/date/string）。
- **跨行别名引用**：`annotate_predefine_line(line, predefines)` 带整段预定义原文（传递链 routes→service→textsearch）；`_pd_alias_names` 只用正则收别名（避免 annotate→parse→annotate 递归环，天然容忍后定义先引用）；`_pd_alias_path_map` 供别名子路径词典（词法器与 simple 旧校验分支共用——**新校验口径必须双分支同步**，只改一处必留口径分叉）。
- **比较键 `_path_key`**：剥单引号 + 去所有空白 + 全角标点转半角，**两侧同键比较**（BOM 有 750+ label 含内部空格/全角标点，只放宽比较不改写展示）。接入：主句/非列表/元素类型名/条件子句全部命中校验与词条注册、列表索引 key。
- **引号平衡计数**：词法器切点仅在引号对闭合处查词典——防止 root"保单"提前命中引号内部、整段错位词被当"别名"假绿。
- **性能**：方法 head 索引按"前 3 必选字符"分桶 + memo 缓存（长表达式单行 25s+ → <1s）；路径扫描改增量归一流（旧 O(n³)）。

### 8. 方法实参类型三连修（2026-09-22/23）

1. **实参含非法操作数被吞**：标注层 `mhit`（方法调用右值）分支原来只在 `arg_bad=True` 时逐 token 着色；槽内含"无法识别的操作数"时 `_pd_slot_type` 见红词返回 None → `arg_bad` 恒 False → 整段实参被吞成 pd_draft 灰显**不报错**。现条件改为 `arg_bad or tokens 内存在 valid is False`——方法名仍绿、括号紫、错误槽红+悬停提示。
2. **`_pd_check_arg_types` 实参×声明类型校验**：方法帧实参槽 vs 注册表 detailsList 声明类型逐位比对，类型族（numeric/string/date）不符→该槽 token `valid=false`（预览标红+阻止上传）。**保守防编辑中误报**：types 缺失/槽数超出/槽空或含未填占位符/槽内已有非法 token/任一侧类型未知→跳过；同族细型（`<integer>` 槽填 double 字段）放行。**issue 保持 warning 级**：`expr["ok"]` 只由 error 级 issue 决定，不翻转（翻转破坏词条注册等既有口径）。
3. **未定义别名引用标红**：带引号 `'X'` 不在已定义别名集时，旧口径只发 warning 级 issue 不标红——而 warning 在 words 渲染层**无消费方=完全静默**，填进 `<double>` 槽也因 alias 类型未知跳过判型，用户看到不报错。现词法器两处（引号段分支 + `_pd_emit_bad_operand` alias 分支）token 置 `valid=false`+error"引用了未定义的预定义别名"；issue 仍 warning 级（同上不动 ok）。已定义别名正常引用/自引用不红（回归保障）。

**排查"该红没红"分层法**：词法器 token 是否已置红（`_pd_lex`/`_pd_emit_bad_operand`）→ 标注层分支是否把 tokens 渲染出来（mhit 等着色分支条件）→ issue level 与前端消费链路（words 无 issues 字段，warning 不可见）。

### 9. 展示着色
预览区按类型着色：keyword/connector 蓝、operator/pd_op 紫、field/object/pd_path/pd_alias 绿、boolean 琥珀、number/value 灰、输入中 pd_draft 浅灰、methodtext 绿；引导词黑粗 1.2em；`valid=false` 红+波浪线+title。

## 九、已知边界（v2）

- 候选基于字符/n-gram 匹配，无语义；字段名需与 BOM label 一致；LLM/语义索引未接入。
- 数值型 string 字段无法区分（统一允许数字）；布尔外层表达式（`( 共保为是 ) 等于 不成立`）已支持嵌套布尔子树（BoolSub，见求值器），但"等于 不成立"字面语义暂不特殊处理。
- 编辑区不显示着色/标红（textarea 限制），需在预览区查看。
- **annotate 与 RuleGenerator 语法不完全一致**：参数列表括号块后直接接"并且/或者"（缺 `为 是`）annotate 放行、生成端报"方法后未知操作符"——统一两端语法规则是待办。
- **预定义右值语法边界**：算术表达式/别名引用已支持（"八·7"），但样本中 `帮助.(x)保留2位小数` 后置修饰等零星形态仍不支持；右值路径未命中当前 BOM（跨库样本）标红属数据版本差异非缺陷。
- **"符合条件"子句**：只解析第一个条件，`并且` 多条件、`是{…}中的一个` 值集未结构化；真实样本主流形态是无"的"字段链（`当前这个X是主险`），编辑器引导的是 `X的<字段>` 形态；条件字段名含"是/不是/包含"时与运算符歧义（正则排除，与生成端一致）；值自由输入不弹枚举候选。
- **预定义变量引用**：预定义行解析失败即不注入词条，规则行引用会被标红；三级字段运算符为借用同类型 BOM 字段的近似集。
- **`_predefine_entries` 正则**：`为一个[^来]*来自` 遇类型名含"来"字会截断（当前样本无此类）。
- **then/else 参数位候选是提示辅助**：参数值仍只查空+类型族校验（"八·8"），不做 BOM 命中强校验；无 expressionArray 的方法靠 BOM label 槽位兜底，无法精确定位时不弹参数候选。
- **上传格式差异**：predefineContent 含编辑辅助空格（`来自(in)`、`为一个 X`），ADP 原始样本为 `来自( in )`、`为一个X`——`_predefine_entries` 两种均能解析，暂按原样上传。
- **求值器边界**：宽容相等使 `'060051'` 与数字 `60051` 判等（编号前导 0 语义无影响面）；填空模式 METHOD 参数字段不列入填空（本地不执行方法）；STR_INCLUDE 列表按"成员或子串任一"宽容判定，未实测 ADP 原始语义；内部字段缺失的嵌套布尔子树按 False 计并给 warning。
- **ADP 环境**：8902 服务时通时断，"登录失败"先直连复测；单条测试初始化异常 1034 两大根因=string 型列表名字段套了数组 / 误填占位符。

## 十二、主系统集成（iframe 内嵌）

> 部署生产化路线（Nginx 反代两阶段、token 方案 A~D 对照）见专题文档 `编辑器集成部署方案.md`。本节只记已落地形态。主系统为编译产物 `dist(2)(1)/dist`（vue-element-admin 变体，**无源码权限，改动直接打 JS 补丁**）。

### 12.1 内嵌形态与 token
- 入口：主系统 `dist/config/indexConf.js` `customPages` 数组（`{path,title,url,roles}`），custom 路由组件动态生成 `<iframe>`。`roles` 只控菜单可见性，编辑器本身无鉴权（收紧见部署文档阶段一）。iframe 地址若仍配 8010 需改 8009。
- **token 注入 postMessage（推荐）**：编辑器就绪发 `{type:"ruleEditorReady"}`，父页面回推 `{type:"adpToken", token}`；不落 URL、支持热更新；编辑器仅接收 `event.source===window.parent` 且用户手改过输入框后不再覆盖。监听脚本已注入 dist `index.html`（备份 `.bak`，**主系统重新构建会冲掉，需复打**）。URL `?token=` 兜底通道编辑器侧保留（单测调试用），主系统侧拼接已删除。
- **CORS 已移除**：前端 fetch 全部同源相对路径；无 token 上传/测试后端直接拒绝（2026-09-17 安全加固，Web 链路无账号密码通道，库层 `login()`/CLI/独立脚本保留）。

### 12.2 切规则库 custom 菜单消失（主系统 bug，已打补丁）
根因：左侧菜单由 `SET_TERRACE` 整体重建，`customPages` 仅靠 navbar mounted 一次 push；平台切换有重注入、规则库切换没有。修法：两处打包 JS（`static/index-BcbvtbP9.js` `changeApplication`、`static/js/index-BEBUDETp.js` `handleApplication`）在 `dispatch("permission/changeRoutes","main")` 后补 `permission/SET_CUSTOMLINK` 重注入（mutation 幂等）。备份 `.bak`；**主系统重新构建需复打**；F5 临时急救。

### 12.3 切菜单必刷新 → 编辑器端 localStorage 持久化
主系统 `<router-view>` 无页面缓存，切菜单 iframe 整页重载。编辑器侧三个 key 等效"页面没刷新过"（均**不存 token**、不存结果面板）：
- `rule_editor_draft_v1`：正文+8 上传参数+光标+高级区展开态；400ms 防抖 + `beforeunload`/`pagehide` 兜底；上传成功/点清空/放弃草稿时删。
- `rule_editor_page_v1`：上传后派生现场（测试报文骨架、`filledValues`、填空卡值按 fieldPath 键、`lastRuleContent`/refs、JSON 视图开关、容器滚动；**2026-09-30 测试报文卡移除后 `setTestMsg` 短路，skeleton/`filledValues`/rawJson 字段不再写入，快照实际只剩填空卡现场**）；上传成功 `savePageNow()` 后才 `clearDraft()`；填空回填值一次性消费防污染；**放弃草稿=`resetPageState()`**（存储与内存派生态一起清，只 removeItem 会被卸载兜底写回）。
- `rule_editor_boot_v1`：**缓存作废机制**——后端进程启动生成 `BOOT_ID`（`GET /api/boot_id`），前端启动比对，不一致（服务重启/换库重建）即删 draft+page 再记新值；接口不可达保留缓存，fetch 1.5s 超时兜底照常恢复。
- 测试注意：草稿恢复须真实输入触发防抖落盘再 reload（直接 setItem 会被旧页 unload 兜底覆盖）；注入用 `add_init_script`（document-start）。
