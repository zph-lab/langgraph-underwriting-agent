# 智能规则编辑器（ilog）—— 交接文档（精简版）

> 最后更新：2026-09-24
> 完整版见 `交接文档.md`

## 一、项目是什么

基于 ilog 规则引擎 + BOM 业务对象模型的**自由文本规则编辑器（v2）**：用户像写自然语言一样直接输入规则文本，系统按空格分隔的语义单元智能补全候选 + 合法性校验，最终文本即规则本身。

```
如果 保单的个团标志 是 动态域集的个团标志的团单
预定义 指定'当前险别'为一个 063048xxx 来自(in) '保单'的人身险信息的063048xxx险别列表
那么 设置061002人身意外伤害保险险别代码为12749
```

> 不再从规则样本（`*_samples.jsonl`）取样生成注册表（`--gen-methods` 仅作临时排查用）：样本里的 expressionId/参数结构是历史快照，可能与当前 BOM 模型错位。车险注册表已于 2026-09-14 纯 rule_model 口径重建。

### expressionId 口径（BOM 与 rule_model.txt 的两层关系，2026-09-16 补，必读）

**分工是死的：BOM 管"入口"，rule_model.txt 管"身份"。**

1. **BOM 方法节点 = 候选/结构的唯一来源**：then/else 候选文案（label）、参数切分槽位、参数类型（detailsList）、fieldPath 全部以 BOM 为准。BOM 没有方法节点的动作，编辑器弹不出来，注册表也不该有它——`--gen-methods-model` 是 **BOM 驱动**的：遍历 BOM 方法节点，逐条去 rule_model.txt 找真实 expressionId，找不到（方法名/文案都匹配不上）就跳过。
2. **expressionId = 永远取自 rule_model.txt，禁止用「类名_field」派生名冒充**：rule_model.txt（ADP 当前方法模型导出）每行 `id \t 文案 \t methodId \t 类#方法#参数`，第 3 列 methodId 就是上传用的 expressionId。派生名（如 `AppBaseFack_migrateSetcrenewtyp`）在 ADP 侧不存在，直接上传必失败。
3. **生成器匹配两档**（`generate_methods_registry_from_model`）：先按（类简名, 方法名, 参数个数, label）与第 4 列签名匹配；BOM 节点方法名与模型错位时按 **label 文案归一化相等**降级匹配（`_norm_method_label`）。
4. **上传侧同口径兜底**（`find_registry_entry`，2026-09-16 修）：注册表条目按 BOM 节点 `类名_field` 前缀查不到时，**按 label 文案与注册表条目相等再查一轮**，保证 expressionId 仍落回 rule_model 的真 id。脏数据实例：`新车险915/bom.json` 中 4 个"设置保单Fack的上年赔款金额为"节点 field 挂成了 `migrateSetcrenewtyp`，而 rule_model 里该方法真名是 `migrateSetnclaimamount`（expressionId=`AppBaseFack_migrateSetnclaimamount`）——按文案照样能映射对，但建议推动 ADP 侧把 BOM 节点方法名修正。
5. **换 BOM 或 rule_model.txt 后必须重跑 `--gen-methods-model` 并重启服务（8009）**（注册表启动时加载进内存）。旧注册表可能是兜底逻辑加入前生成的：新车险915 于 2026-09-16 重建后 529 → 593 条，新增的 64 条正是"BOM 方法名错位、只能按 label 文案对上"的那批。
6. **验证过的四例**（文案 → expressionId）：`设置保单Fack的上年赔款金额为→AppBaseFack_migrateSetnclaimamount`、`设置保单的续保类型为→AppBase_migrateSetcrenewtyp`、`设置平台无赔款优待及上年赔款记录为→PlatformPremcoefInfo_migrateSetpremfactor1`、`设置保单Fack的关联单类型为→AppBaseFack_migrateSetrelationType`。注意"上年赔款金额"（Fack）与"续保类型"（AppBase）是错位关系下的两个不同方法，靠文案区分，不可互串。

## 五、环境注意

- `config.yaml` 当前数据源为 `非车销售/bom.json`；切回 `车险/` 改 config 并重跑 ETL。
- v2 主流程只需 `data/bom_catalog.sqlite`；TextSearchService 启动时一次性建内存索引。
- 命中测试需 ADP 可达（`http://192.168.0.205:8902`）；填空模式测试纯本地，不需要网络。
- Windows 下重启服务若端口被旧进程占用，按端口找 PID 杀（`Get-NetTCPConnection -LocalPort 8009` → `taskkill`），否则新代码不生效。**8010 现为用户其他服务专用端口，编辑器一律用 8009**（旧 `_restart8010.ps1` 作废勿用）。
- 编辑器条件子表达式括号须用**英文括号 `()`**（生成端括号组解析只认半角，全角 `（）` 会报"缺右括号"）。
- 运算符注册表分两处生效口径（2026-09-15 补 `不等于(NE)`/`不属于…中的一个(STR_NOT_BELONG_TO)` 时确认）：`rule_tree.OPERATOR_META`/`phrase_grammar.OPERATOR_RENDER`/`desc_codec.op_map` 是运行时模块，**改后重启服务（8009）即生效**；`bom_catalog.TYPE_OPERATORS` 决定字段运算符**下拉候选**，ETL 建库时写入 `field_operators` 表，**新增运算符须重跑 `python -m rule_editor.etl.run_etl` 重建 bom 库**才会出现（`desc→rulecontent` 与本地求值 `rule_evaluator` 早已支持这两个运算符，无需改）。`desc_codec.op_map` 子串匹配、首命中即止，**否定式必须排在肯定式前**（不属于<属于、不等于<等于、不包含<包含）。
