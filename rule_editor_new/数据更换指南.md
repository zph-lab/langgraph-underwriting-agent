# 数据更换指南（当前数据源：新车险915）

> 本编辑器**不含内置业务模型**，所有候选、校验、上传产物都来自一套外部数据（当前为
> `新车险915/`，即按"新车险915"业务模型建库）。换一套数据 = 换这一整套，
> **缺一步都可能造成"候选能弹但上传报错"这类两口径分叉**。本文给出完整换法与校验清单。
>
> 配套阅读：`交接文档.md`（架构与接口全貌）、`交接文档_精简版.md`（命令速查）。
> 服务端口 **8009**（`config.yaml`），重启一律用根目录 `_restart8009.ps1`（8010 已另作他用）。

## 一、数据依赖总览（谁读哪份数据）

| 文件（相对项目根） | 作用 | 读取方 | 换库不更新的后果 |
|---|---|---|---|
| `新车险915/bom.json` | **BOM 业务模型树（最核心）**：对象/字段/列表路径/方法节点/参数类型（detailsList）的唯一来源 | `core/textsearch.py`（候选、预定义列表索引、标注校验，直读该文件）、`etl/run_etl.py`（建 bom_catalog）、上传接口 `routes._default_bom_path` | 候选/校验全是旧模型 |
| `新车险915/rule_model.txt` | ADP 导出的回写方法表：`id \t 文案 \t methodId \t 类#方法#参数`，**expressionId 唯一权威来源** | 仅用于生成方法注册表（`--gen-methods-model`） | then/else 上传用错/旧 expressionId，ADP 保存失败 |
| `新车险915/repository.txt` | 决策库对照表 `库名 \t repositoryId` | `etl/repositories.py` → `data/bom_catalog.sqlite` 的 `repositories` 表 → 前端"选库"面板 | 选库面板列表缺失（可手输 ID，不阻塞） |
| `新车险915/respository_cata.txt` | 决策分类对照表 `分类名 \t repositoryId \t catalogueId`（文件名拼写沿用原样，勿"纠正"） | 同上 → `catalogues` 表 → "选分类"面板 | 同上 |
| `data/bom_catalog.sqlite` | **ETL 产物**（git 屏蔽，勿手工编辑）：BOM 展平表 + 运算符兼容表 + 库/分类对照表 | 服务启动/每请求读库（选库选分类即查库） | 换 bom 不重跑 ETL = 前端候选新、后端校验旧 |
| `desc_to_rulecontent/bom_methods_<目录名>.json` | then/else **方法注册表**（真实 expressionId + expressionArray 模板），当前为 `bom_methods_新车险915.json`（593 条） | `textsearch` 懒加载进内存（方法候选/参数位切分）、上传转换 `find_registry_entry` | 见下方"坑 2"：会**静默回退** `bom_methods_非车.json`，BOM 与模板文案错位 |
| `rule_editor/config.yaml` | 一切路径与配套 ID 的**总开关** | 全局 | — |

`config.yaml` 中与数据源绑定的键（换库必改清单）：

```yaml
data:
  bom_path: "新车险915/bom.json"          # ① 新目录/bom.json
  samples_dir: "新车险915"                # ② 新目录（末级目录名决定注册表文件名，见坑 2）
  repository_file: "新车险915/repository.txt"    # ③
  catalogue_file: "新车险915/respository_cata.txt" # ④
upload:
  url: "http://192.168.0.205:8902/decision/rule"
  bom_base_info_id: "f8e7be25..."         # ⑤ 必须换：新 BOM 基础信息 ID（ADP 侧）
  bom_model_id: "cdee52e7..."             # ⑥ 必须换：新规则所属 BOM 模型 ID（保存那么/否则必填）
```

> ⑤⑥ 与 BOM 数据源及目标决策库**三者配套**（config 注释已强调）：bom.json 是模型 A 的，
> bom_base_info_id/bom_model_id 就必须是模型 A 在 ADP 的 id，repositoryId/catalogueId 也须是
> 挂了模型 A 的决策库/分类，否则预览全绿、上传必失败。

## 二、换数据标准流程

以换到 `新数据X/` 为例，六步按序做完，**不要跳步**：

### 第 0 步：备份
备份 `rule_editor/config.yaml`；`data/` 与旧 `bom_methods_*.json` 是产物可随时重建，不必备份原始件，但建议留旧数据目录以便回退。

### 第 1 步：放入新数据目录
项目根新建 `新数据X/`，**目录名会直接用作注册表文件名**（`bom_methods_新数据X.json`），先定好名。必备：

- `bom.json`（ADP 导出的业务模型树）
- `rule_model.txt`（ADP 导出的回写方法表）
- `repository.txt`、`respository_cata.txt`（决策库/分类对照表；可缺，缺则面板空、不阻塞）

对照表解析容忍 Tab/逗号/空白分隔与列序、utf-8/gbk 均可，表头行自动跳过。

### 第 2 步：改 config.yaml
按上文"键清单"①—④ 改成新目录；⑤⑥ upload 两个 id 换成新 BOM 模型在 ADP 的
`bomBaseInfoId`/`bomModelId`（向 ADP 侧索取，或从目标库的模型详情里查）。

### 第 3 步：重建方法注册表（BOM 管入口，rule_model 管身份）
```powershell
python desc_to_rulecontent\write_rule_to_adp.py --gen-methods-model "新数据X\bom.json" --model-methods "新数据X\rule_model.txt"
```
输出按目录名自动命名 `desc_to_rulecontent\bom_methods_新数据X.json`。
**BOM 或 rule_model.txt 任一有变动都要重跑此步**；禁止用样本口径 `--gen-methods`（历史快照会错位，仅临时排查）。

### 第 4 步：重跑 ETL（重建 data/ 产物 + 两张对照表）
```powershell
python -m rule_editor.etl.run_etl
```
核心产物：`data/bom_catalog.sqlite`（v2 主流程唯一必用库；run_etl 另会产出几个辅助 sqlite，主流程不读）。
只换了库/分类对照表时可用轻量入口（drop-recreate 单表，不动其他）：
```powershell
python -m rule_editor.etl.repositories
```

### 第 5 步：重启服务（8009）
```powershell
.\_restart8009.ps1
```
必须重启：`textsearch` 的 BOM 路径索引/预定义列表索引/方法注册表都缓存在内存，
ETL 也改了 sqlite。仅刷了 repositories/catalogues 两张对照表可不重启（接口每请求现查，前端刷新即见）。

### 第 6 步：校验清单（全过才算换完）
```powershell
# 1) 服务与数据规模
curl http://127.0.0.1:8009/api/health          # stats 里 BOM 节点/路径数量应≈新模型规模
```
浏览器 `http://127.0.0.1:8009` 逐项：
- [ ] `如果` 行检索一个**新模型才有的字段路径**能出候选（证明读的是新 bom）；
- [ ] 一个**旧模型独有**的路径不再出现（证明内存索引已换新）；
- [ ] `预定义 指定'测试'为一个 …来自(in) …` 列表路径能命中新 BOM 的 type=list 节点；
- [ ] `那么` 动作能弹出新模型方法、带占位模板（证明新注册表已加载）；
- [ ] 上传卡片"选库/选分类"面板列出新对照表；
- [ ] 挑一条完整规则 `生成`（/api/generate_rule，离线）成功，再对测试库真实上传一条验证 `bomModelId` 配套。

## 三、Docker 部署的差异

`Dockerfile` 里数据目录是**写死的**：

```dockerfile
COPY 新车险915/ ./新车险915/     # ← 换目录名要同步改这行
COPY data/ ./data/               # ETL 产物随镜像发布
COPY desc_to_rulecontent/ ./desc_to_rulecontent/   # 含 bom_methods_*.json
```

两种做法：
- **重建镜像**（数据随镜像固化）：改 Dockerfile 的 COPY 行 + config.yaml，`docker build` 后起容器。
- **挂载热换**（推荐迭代期用）：`docker-compose.yml` 已注释好挂载示例，放开
  `./新数据X:/app/新数据X`、`./data:/app/data`、`./desc_to_rulecontent:/app/desc_to_rulecontent`
  三行（**去掉 `:ro`**，否则容器内跑不了 ETL/写不回注册表），config.yaml 默认只挂 `:ro` 那份改好后
  `docker compose restart` 即生效。compose 映射的是宿主机 8010（容器内 `PORT=8010`），
  本地裸跑固定 8009，两者互不冲突。

容器内重建 ETL：`docker compose exec rule-editor python -m rule_editor.etl.run_etl`
（需挂载 data 为可写）。

## 四、易踩的坑（历史踩过/代码注释明确警告的）

1. **只换 bom.json 不重跑 ETL/注册表**：预览候选与上传产物分叉——候选来自新 bom 内存索引，
   ruleContent 却拿旧注册表的 expressionId。第 3、4 步一个都不能少。
2. **注册表静默回退**：`write_rule_to_adp.default_methods_registry()` 按
   `bom_methods_<samples_dir 末级目录名>.json` 找文件，**找不到会回退 `bom_methods_非车.json`**，
   不报错。所以第 3 步生成后确认文件名与 `samples_dir` 目录名逐字一致。
   同理别把 `samples_dir` 配成绝对路径后再手拼注册表名（代码只取末级目录名）。
3. **expressionId 口径**：永远以 `rule_model.txt` 为准，BOM 与 rule_model 方法名可能错位
   （生成器有按 label 文案归一的降级匹配，2026-09-16 新车险915 重建时 529→593 条中 64 条就靠它）。
   看到注册表条数明显少于 BOM 方法数，就是 rule_model.txt 与 bom.json 不是同一模型/同一时期的导出。
4. **`data.bom_path` 留空的兜底陷阱**：`routes._default_bom_path()` 只兜底找
   `车险/bom.json`、`非车销售/bom.json`，两个都不存在时直接 `RuntimeError: 未找到 BOM 文件`。换库时
   ①②③④ 四项要整组替换，不要留旧值半套运行。
5. **`samples_dir` 是 run_etl 的必到输入目录**：指向的目录不存在时 ETL 直接抛异常（哪怕空目录）；
   其末级目录名同时决定注册表文件名，与 ② 一起改、别拆。
6. **改任何 Python/ETL 产物必须重启 8009**；只改前端 `web/` 刷新浏览器即可。Windows 下按端口找 PID
   杀旧进程（脚本已封装），BOM 较大时启动慢，脚本报 boot_id 探活失败就再轮询几秒端口。
7. **运算符词形**（如新增运算符）不是换数据能带过来的：运行时词表在
   `rule_tree.OPERATOR_META`/`phrase_grammar`/`desc_codec` 代码里（改后重启生效）；
   字段-运算符兼容候选来自 ETL 写的 `field_operators` 表（换 bom 重跑 run_etl 自动更新）。
   参考根目录 `运算符924.txt`。
